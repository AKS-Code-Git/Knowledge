Part 1 · Functional Foundations

Functional Programming Basics

KEY KNOWLEDGE

  • Functional programming builds software from pure functions, immutable data and function composition. Java is multi-paradigm: since Java 8 lambdas, method references, streams and Optional let you write declarative, side-effect-free code on top of its object model.
  • A pure function depends only on its inputs and has no side effects, so it is easy to test, cache and run in parallel.

Q1. What is functional programming?

A programming paradigm that builds programs by composing functions, treating functions as first-class values, and favoring immutability and side-effect-free computation over mutable state.

Q2. What are the core principles of functional programming?

Pure functions, immutability, first-class and higher-order functions, function composition, declarative style, and avoiding shared mutable state.

Q3. What is a pure function?

A function whose output depends only on its inputs and which causes no side effects (no mutation of external state, no I/O). Same input always gives same output.

↑ Contents6

Functional Programming Basics · continued

Q4. What is a side effect?

Any observable change outside a function's return value, such as modifying a field, writing to a file, printing, or throwing exceptions that affect control flow.

Q5. What is referential transparency?

An expression is referentially transparent if it can be replaced with its value without changing program behavior. Pure functions have this property.

Q6. What is a higher-order function?

A function that takes one or more functions as parameters, returns a function, or both. Examples: Stream.map(), Comparator.comparing().

Q7. What does "functions as first-class citizens" mean?

Functions can be assigned to variables, passed as arguments, and returned from methods. In Java this is achieved through lambdas and functional interfaces.

Q8. Is Java a functional programming language?

No. Java is primarily object-oriented, but since Java 8 it supports functional features such as lambdas, method references, streams, and Optional, making it multi-paradigm.

7

Functional Programming Basics · continued

Q9. What is immutability and why does it matter?

An immutable object cannot change after creation. It is thread-safe by nature, easier to reason about, and ideal for functional code and parallel processing.

Q10. What is the difference between imperative and declarative programming?

Imperative code describes HOW to do something step by step (loops, mutation). Declarative code describes WHAT result is wanted (e.g., stream pipelines).

Q11. What is function composition?

Combining two or more functions so that the output of one becomes the input of the next. In Java: Function.andThen() and Function.compose().

Q12. What is currying?

Transforming a function with multiple arguments into a chain of single-argument functions. In Java: Function<Integer, Function<Integer, Integer>> add = a -> b -> a + b;

Q13. What is partial application?

Fixing some arguments of a function to produce a new function with fewer parameters, e.g., Function<Integer,Integer> add5 = x -> add.apply(5).apply(x);

↑ Contents8

Functional Programming Basics · continued

Q14. What is lazy evaluation?

Deferring computation until its result is needed. Java streams evaluate intermediate operations lazily, only running when a terminal operation is invoked.

Q15. What are the benefits of functional programming in Java?

Concise code, better readability, easier parallelism, fewer bugs from shared state, improved testability, and more reusable, composable logic.

Lambda Expressions

KEY KNOWLEDGE

  • A lambda is an anonymous function: parameters, an arrow and a body. It can target any functional interface (one abstract method) and captures only final or effectively final local variables.
Runnable r = () -> System.out.println("hi");
BiFunction<Integer,Integer,Integer> add = (a, b) -> a + b;
int base = 10;                       // effectively final
Function<Integer,Integer> plus = x -> x + base;

    Q16. What is a lambda expression?

    An anonymous function with optional parameters and a body that can be used wherever a functional interface is expected. Syntax: (params) -> expression or (params) -> { statements; }.

    Q17. What is the syntax of a lambda expression?

    Three parts: parameter list, arrow token ->, and body. Example: (a, b) -> a + b.

    Q18. When can parentheses around lambda parameters be omitted?

    When there is exactly one parameter with an inferred type, e.g., x -> x * 2. Zero or multiple parameters require parentheses.

    Q19. When can braces and the return keyword be omitted?

    When the body is a single expression. The expression's value is returned implicitly. Multi-statement bodies need braces and an explicit return if a value is returned.

    ↑ Contents10

    Lambda Expressions · continued

    Q20. What is a functional interface?

    An interface with exactly one abstract method (SAM). It can have default, static, and Object-class methods. Lambdas provide its implementation.

    Q21. What is the @FunctionalInterface annotation?

    An optional marker that makes the compiler verify the interface has exactly one abstract method, producing a compile error otherwise. It documents intent and protects against accidental changes.

    Q22. Can a lambda expression exist without a functional interface?

    No. A lambda's type is always inferred from the target functional interface context.

    Q23. What is target typing in lambdas?

    The compiler infers the lambda's type from the context where it is used (assignment, method argument, return statement, cast).

    Q24. What are effectively final variables?

    Local variables that are never reassigned after initialization. Lambdas may capture local variables only if they are final or effectively final.

    Q25. Why must captured local variables be effectively final?

    Local variables live on the stack and lambdas may run later or on another thread; capturing a copy that cannot change avoids inconsistency and thread-safety issues.

    11

    Lambda Expressions · continued

    Q26. Can a lambda modify instance or static variables?

    Yes. Instance and static fields live on the heap and can be modified, though doing so introduces side effects and thread-safety concerns.

    Q27. What does the "this" keyword refer to inside a lambda?

    The enclosing class instance, not the lambda itself. This differs from anonymous inner classes where this refers to the anonymous object.

    Q28. What are the differences between lambdas and anonymous inner classes?

    Lambdas are shorter, can only implement functional interfaces, do not create a new scope for this, and are compiled using invokedynamic rather than generating separate class files.

    Q29. How are lambdas implemented under the hood?

    The compiler turns the body into a private synthetic method and uses invokedynamic with LambdaMetafactory to create the functional interface instance at runtime.

    Q30. Can a lambda throw checked exceptions?

    Only if the functional interface's abstract method declares them. Standard interfaces such as Function do not, so you must wrap the code in try-catch or use a custom interface.

    ↑ Contents12

    Lambda Expressions · continued

    Q31. How do you handle checked exceptions inside stream lambdas?

    Catch the exception inside the lambda and wrap it in an unchecked exception, or create a wrapper utility or custom functional interface that rethrows.

    Q32. Can lambdas be recursive?

    Not directly because a lambda cannot refer to itself in its initializer. Workarounds include using a field or class-level variable, or a helper like a Function holder.

    Q33. Can a lambda have a variable with the same name as an enclosing local variable?

    No. Lambda parameters and locals cannot shadow local variables of the enclosing scope; this causes a compile error.

    Q34. Are lambdas objects?

    Yes, at runtime a lambda is an instance of the target functional interface, though it is not necessarily a new object each time (non-capturing lambdas may be cached).

    Q35. What is a closure in Java?

    A lambda that captures variables from its enclosing scope. Java closures capture values, not variables, hence the effectively final rule.

    Functional Interfaces

    KEY KNOWLEDGE

    • The java.util.function package supplies the standard shapes: Function (T to R), Predicate (T to boolean), Consumer (T to nothing), Supplier (nothing to T), plus Bi- variants, operators and primitive specializations that avoid boxing.
    Predicate<String> longWord = s -> s.length() > 5;
Function<String,Integer> len = String::length;
Predicate<String> p = longWord.and(s -> s.startsWith("j")).negate();
Function<Integer,Integer> f = len.andThen(n -> n * 2).compose(Object::toString)::apply;

      Q36. List the main functional interfaces in java.util.function.

      Function, BiFunction, Predicate, BiPredicate, Consumer, BiConsumer, Supplier, UnaryOperator, BinaryOperator, plus primitive specializations.

      Q37. What is the Function interface?

      Function<T,R> has the abstract method R apply(T t). It transforms a value of type T into type R.

      Q38. What is the Predicate interface?

      Predicate<T> has boolean test(T t) and is used for conditions and filtering.

      Q39. What is the Consumer interface?

      Consumer<T> has void accept(T t). It performs an operation on a value and returns nothing, typically with side effects.

      ↑ Contents14

      Functional Interfaces · continued

      Q40. What is the Supplier interface?

      Supplier<T> has T get(). It takes no input and supplies a value, useful for lazy creation.

      Q41. What is the BiFunction interface?

      BiFunction<T,U,R> has R apply(T t, U u), taking two arguments and returning a result.

      Q42. What is UnaryOperator?

      UnaryOperator<T> extends Function<T,T>; input and output are the same type.

      Q43. What is BinaryOperator?

      BinaryOperator<T> extends BiFunction<T,T,T>; two inputs and one output all of the same type. Also offers static minBy and maxBy.

      Q44. What are the default methods of Predicate?

      and(), or(), negate(), and static methods isEqual() and not() (Java 11).

      Q45. What is the difference between Function.andThen() and Function.compose()?

      f.andThen(g) applies f first then g; f.compose(g) applies g first then f.

      15

      Functional Interfaces · continued

      Q46. What does Function.identity() do?

      It returns a function that always returns its input argument, commonly used in Collectors.toMap(Function.identity(), ...).

      Q47. What are primitive specializations of functional interfaces and why do they exist?

      Interfaces such as IntPredicate, IntFunction, ToIntFunction, IntSupplier, and IntBinaryOperator avoid autoboxing overhead for int, long, and double.

      Q48. What is the difference between Function and ToIntFunction?

      Function<T,Integer> boxes its result, whereas ToIntFunction<T> returns a primitive int via applyAsInt, avoiding boxing.

      Q49. What is BiConsumer used for?

      It accepts two arguments and returns nothing, e.g., Map.forEach((k, v) -> ...).

      Q50. What is BiPredicate?

      BiPredicate<T,U> with boolean test(T t, U u) evaluates a condition on two arguments.

      Q51. What is the difference between Runnable, Callable, and Supplier?

      Runnable.run() takes nothing and returns nothing; Callable.call() returns a value and may throw checked exceptions; Supplier.get() returns a value and throws no checked exceptions.

      ↑ Contents16

      Functional Interfaces · continued

      Q52. How do you create a custom functional interface?

      Declare an interface with a single abstract method, optionally annotated with @FunctionalInterface, e.g., interface TriFunction<A,B,C,R> { R apply(A a, B b, C c); }.

      Q53. Can a functional interface extend another interface?

      Yes, as long as the combined interface still has exactly one abstract method, including inherited ones.

      Q54. Can a functional interface declare methods of Object like equals()?

      Yes. Methods matching public methods of Object do not count toward the single abstract method limit (e.g., Comparator.equals).

      Q55. Is Comparator a functional interface?

      Yes. Its single abstract method is compare(T,T); the many other methods are default or static.

      Q56. How do you chain Predicates?

      Use and, or, and negate: Predicate<String> p = isLong.and(startsWithA).negate();

      Q57. What are default methods in interfaces and how do they relate to functional programming?

      Default methods provide concrete behavior inside interfaces, letting APIs like Collection and Comparator add functional methods without breaking existing implementations.

      17

      Functional Interfaces · continued

      Q58. Can a functional interface have static methods?

      Yes. Static methods are allowed and do not affect the abstract-method count, e.g., Predicate.not().

      Q59. What is a Supplier used for in lazy evaluation?

      It delays creation or computation until get() is called, e.g., Optional.orElseGet(Supplier) or lazy logging.

      Q60. How does a lambda decide which functional interface overload to call?

      Through target typing and parameter/return shape. Ambiguity (such as Runnable vs Callable) can be resolved with a cast or explicit typing.

      Method References

      KEY KNOWLEDGE

      • A method reference (Class::method) is shorthand for a lambda that only calls one existing method. There are four kinds: static, bound instance, unbound instance and constructor references.
      list.forEach(System.out::println);          // bound instance
list.stream().map(String::toUpperCase);      // unbound instance
list.stream().map(Integer::parseInt);        // static
Supplier<List<String>> s = ArrayList::new;   // constructor

        Q61. What is a method reference?

        A shorthand for a lambda that simply calls an existing method, written as Class::method.

        Q62. What are the four types of method references?

        Static method (Integer::parseInt), instance method of a particular object (System.out::println), instance method of an arbitrary object of a type (String::length), and constructor (ArrayList::new).

        Q63. What is a static method reference?

        A reference to a static method, e.g., Math::abs equals x -> Math.abs(x).

        Q64. What is a bound instance method reference?

        A reference to a method on a specific existing object, e.g., str::concat equals x -> str.concat(x).

        ↑ Contents22

        Method References · continued

        Q65. What is an unbound instance method reference?

        A reference where the first lambda argument becomes the receiver: String::toUpperCase equals s -> s.toUpperCase().

        Q66. What is a constructor reference?

        A reference to a constructor using ::new, e.g., Supplier<List<String>> s = ArrayList::new;

        Q67. How do you create an array using a method reference?

        Use an array constructor reference: IntFunction<int[]> f = int[]::new; or toArray(String[]::new).

        Q68. When should you prefer a method reference over a lambda?

        When the lambda only delegates to an existing method; it is shorter and clearer. Use a lambda when extra logic is required.

        Q69. Can method references be used with overloaded methods?

        Yes, the compiler picks the overload matching the target functional interface's signature; ambiguity produces a compile error.

        Q70. What is the difference between this::method and super::method?

        this::method refers to the current instance's method; super::method refers to the superclass implementation.

        23

        Method References · continued

        Q71. How is a method reference different from a lambda at runtime?

        Functionally equivalent, but method references may compile directly to a method handle without creating a synthetic lambda method.

        Q72. Give an example of Comparator using method references.

        list.sort(Comparator.comparing(Person::getName).thenComparing(Person::getAge));

        Part 2 · Optional and Stream Basics

        Optional

        KEY KNOWLEDGE

        • Optional<T> is a container that may or may not hold a value. Use it as a return type to make absence explicit, and prefer map, flatMap, filter and orElse* over isPresent plus get.
        String city = Optional.ofNullable(user)
    .map(User::getAddress)
    .map(Address::getCity)
    .orElse("Unknown");

          Q73. What is Optional in Java?

          A container object introduced in Java 8 that may or may not hold a non-null value, designed to express absence explicitly and reduce NullPointerException.

          Q74. How do you create an Optional?

          Optional.of(value) (non-null only), Optional.ofNullable(value), and Optional.empty().

          Q75. What happens if you call Optional.of(null)?

          It throws NullPointerException. Use ofNullable when the value may be null.

          ↑ Contents28

          Optional · continued

          Q76. What is the difference between orElse and orElseGet?

          orElse(value) always evaluates its argument; orElseGet(supplier) invokes the supplier only when the Optional is empty, so it is better for expensive defaults.

          Q77. What does orElseThrow do?

          Returns the value if present, else throws the exception provided by a supplier. Java 10 added a no-argument version throwing NoSuchElementException.

          Q78. What is the difference between map and flatMap on Optional?

          map wraps the function's result in an Optional; flatMap expects the function to already return an Optional, avoiding Optional<Optional<T>>.

          Q79. What does Optional.filter do?

          Returns the same Optional if a value is present and matches the predicate; otherwise returns an empty Optional.

          Q80. What do ifPresent and ifPresentOrElse do?

          ifPresent(Consumer) runs an action if a value exists; ifPresentOrElse(Consumer, Runnable) (Java 9) also runs a fallback action when empty.

          Q81. What does Optional.or() do?

          Introduced in Java 9, it returns this Optional if present, otherwise an Optional produced by the supplier.

          29

          Optional · continued

          Q82. What does Optional.stream() do?

          Java 9 method returning a stream of zero or one element, useful with flatMap(Optional::stream) to drop empty Optionals.

          Q83. What does isEmpty() do?

          Java 11 method returning true if no value is present; the inverse of isPresent().

          Q84. Why is calling get() without checking discouraged?

          It throws NoSuchElementException if empty, defeating the purpose of Optional. Prefer orElse, orElseGet, orElseThrow, or ifPresent.

          Q85. Should Optional be used for fields and method parameters?

          Generally no. Optional is intended mainly as a return type; it is not Serializable and adds overhead and awkward call sites when used for fields or parameters.

          Q86. Is Optional serializable?

          No, Optional does not implement Serializable.

          Q87. What are OptionalInt, OptionalLong, and OptionalDouble?

          Primitive Optional specializations that avoid boxing, returned by stream operations like IntStream.max() and average().

          ↑ Contents30

          Optional · continued

          Q88. Can Optional.ofNullable replace null checks completely?

          It helps express nullable returns but is not a drop-in replacement for all null checks, e.g., in collections or performance-critical paths.

          Q89. Is Optional a monad?

          Loosely yes: it supports of (unit) and flatMap (bind), but Java does not formally guarantee monad laws in all edge cases.

          Q90. How do you chain Optionals to avoid nested null checks?

          Use map/flatMap: Optional.ofNullable(user).map(User::getAddress).map(Address::getCity).orElse("Unknown");

          Stream API Basics

          KEY KNOWLEDGE

          • A stream is a lazy, one-shot sequence of elements processed by a pipeline: a source, zero or more intermediate operations and one terminal operation. Streams do not store data and should not modify their source.
          List<String> result = names.stream()      // source
    .filter(n -> n.length() > 3)           // intermediate
    .map(String::toUpperCase)              // intermediate
    .collect(Collectors.toList());         // terminal

            Q91. What is the Stream API?

            A Java 8 API in java.util.stream for processing sequences of elements declaratively through pipelines of operations such as filter, map, and reduce.

            Q92. What is a stream?

            A sequence of elements supporting aggregate operations. It is not a data structure and does not store elements; it pulls them from a source.

            Q93. What are the three parts of a stream pipeline?

            A source (collection, array, generator), zero or more intermediate operations, and exactly one terminal operation.

            ↑ Contents34

            Stream API Basics · continued

            Q94. What is the difference between Collection and Stream?

            A collection stores data in memory and can be traversed many times; a stream is a one-shot, lazy view of computation that does not store data.

            Q95. Can a stream be reused?

            No. After a terminal operation, the stream is consumed and reuse throws IllegalStateException. Create a new stream from the source or use a Supplier<Stream>.

            Q96. How can you create a stream?

            collection.stream(), Arrays.stream(arr), Stream.of(...), Stream.iterate(), Stream.generate(), IntStream.range(), Files.lines(), Stream.builder().

            Q97. What are intermediate operations?

            Operations returning a new stream and executed lazily, such as filter, map, sorted, distinct, limit, and peek.

            Q98. What are terminal operations?

            Operations that trigger pipeline execution and produce a result or side effect, such as collect, forEach, reduce, count, anyMatch, and findFirst.

            Q99. Are streams lazy?

            Yes. Intermediate operations do nothing until a terminal operation starts the pipeline.

            35

            Stream API Basics · continued

            Q100. What is a short-circuiting operation?

            An operation that may stop processing before all elements are consumed, e.g., limit, findFirst, anyMatch, allMatch, noneMatch.

            Q101. What is the difference between stateless and stateful intermediate operations?

            Stateless operations (filter, map) process each element independently; stateful ones (sorted, distinct, limit) need to know about other elements.

            Q102. What is loop fusion in streams?

            Multiple stateless operations are combined into a single pass over the data, with each element flowing through the whole pipeline before the next one starts.

            Q103. What are IntStream, LongStream, and DoubleStream?

            Primitive streams that avoid boxing and provide numeric operations like sum(), average(), range(), and summaryStatistics().

            Q104. How do you convert between object and primitive streams?

            mapToInt, mapToLong, mapToDouble go from object to primitive; boxed() or mapToObj go back.

            Q105. What is the difference between IntStream.range and rangeClosed?

            range(1,5) yields 1 to 4 (end exclusive); rangeClosed(1,5) yields 1 to 5 (end inclusive).

            ↑ Contents36

            Stream API Basics · continued

            Q106. What is an infinite stream and how do you create one?

            A stream with no fixed size, created with Stream.iterate(seed, f) or Stream.generate(supplier); use limit() or takeWhile() to bound it.

            Q107. Do streams modify the source collection?

            No. Streams are non-interfering and should not modify their source; doing so can cause ConcurrentModificationException or undefined behavior.

            Q108. What does "non-interference" mean in streams?

            Behavioral parameters must not modify the stream's data source during pipeline execution.

            Q109. What is the Spliterator?

            An object for traversing and partitioning source elements, enabling both sequential and parallel traversal; it underpins stream sources.

            Q110. How do you stream a String's characters?

            "hello".chars() returns an IntStream of code units; use mapToObj(c -> (char) c) to obtain characters.

            Part 3 · Stream Operations and Collectors

            Intermediate Operations

            KEY KNOWLEDGE

            • Intermediate operations return a new stream and run lazily. Stateless ones (filter, map, flatMap, peek) handle each element independently; stateful ones (sorted, distinct, limit, skip) may need to see other elements.

            Q111. What does filter() do?

            Retains only elements matching a given Predicate: stream.filter(n -> n % 2 == 0).

            Q112. What does map() do?

            Transforms each element using a Function, producing a stream of results: names.stream().map(String::toUpperCase).

            Q113. What is the difference between map and flatMap?

            map is one-to-one; flatMap is one-to-many and flattens resulting streams into a single stream, e.g., turning List<List<T>> into a flat Stream<T>.

            Q114. How do you flatten a list of lists?

            listOfLists.stream().flatMap(List::stream).collect(Collectors.toList());

            ↑ Contents42

            Intermediate Operations · continued

            Q115. What does distinct() do?

            Removes duplicates using equals()/hashCode(), preserving encounter order for ordered streams.

            Q116. What does sorted() do?

            Sorts elements by natural order, or by a Comparator if provided. Elements must be Comparable if no comparator is given.

            Q117. How do you sort in reverse order using streams?

            stream.sorted(Comparator.reverseOrder()) or stream.sorted(Comparator.comparing(Person::getAge).reversed()).

            Q118. What does limit(n) do?

            Truncates the stream to at most n elements; it is short-circuiting.

            Q119. What does skip(n) do?

            Discards the first n elements and returns the rest.

            Q120. How do you implement pagination with streams?

            list.stream().skip((page - 1) * size).limit(size).collect(...).

            Q121. What does peek() do and when should it be used?

            It performs an action on each element as it passes through, mainly for debugging. It should not be relied on for business logic since it may be skipped by optimizations.

            43

            Intermediate Operations · continued

            Q122. What do takeWhile and dropWhile do?

            Java 9 methods: takeWhile takes elements while the predicate is true then stops; dropWhile discards while true then keeps the rest. Best on ordered streams.

            Q123. What is mapToInt and why use it?

            Converts a stream to an IntStream, avoiding boxing and enabling methods like sum() and average().

            Q124. What is mapMulti?

            A Java 16 operation letting each element push zero or more results to a consumer; it can be more efficient than flatMap for small expansions.

            Q125. What does boxed() do?

            Converts a primitive stream into a stream of wrapper objects, e.g., IntStream to Stream<Integer>.

            Q126. What does parallel() and sequential() do?

            They set the whole pipeline's execution mode; the last call before the terminal operation wins.

            Q127. What does unordered() do?

            Signals that encounter order does not matter, possibly allowing more efficient parallel execution for distinct or limit.

            ↑ Contents44

            Intermediate Operations · continued

            Q128. What is the difference between sorted() and sorted(Comparator)?

            The first requires Comparable elements and uses natural order; the second uses the given comparator and works for any type.

            Q129. Is sorted() a stateful operation?

            Yes, it must buffer all elements before emitting any, so it is a barrier in the pipeline.

            Q130. How do you find distinct elements based on a property?

            distinct() uses equals; for property-based distinctness use Collectors.toMap(key, Function.identity(), (a,b) -> a) or a filter with a concurrent set.

            Q131. How do you concatenate two streams?

            Stream.concat(stream1, stream2).

            Q132. What is the order of execution in stream.filter(a).map(b).forEach(c)?

            Element by element: each element passes filter, then map, then forEach before the next element starts (vertical processing).

            Q133. What happens if you place sorted() before limit()?

            All elements are sorted first, then truncated. Placing limit before sorted changes the semantics and result.

            Q134. How do you convert a stream of strings to lengths?

            strings.stream().map(String::length) or mapToInt(String::length).

            Q135. How do you remove null elements from a stream?

            stream.filter(Objects::nonNull).

            Terminal Operations

            KEY KNOWLEDGE

            • A terminal operation starts the pipeline and produces a result or side effect: collect, reduce, forEach, count, min, max, match and find operations, toArray and toList. After it runs, the stream is consumed.
            int total = nums.stream().reduce(0, Integer::sum);
Optional<Integer> max = nums.stream().max(Integer::compare);
boolean any = nums.stream().anyMatch(n -> n > 10);

              Q136. What does forEach() do?

              Performs an action on each element; it is a terminal operation and does not guarantee order for parallel streams.

              Q137. What is the difference between forEach and forEachOrdered?

              forEachOrdered respects encounter order even in parallel streams, at some cost to parallel performance.

              Q138. What does collect() do?

              A mutable reduction that accumulates elements into a container (list, set, map, string) using a Collector.

              Q139. What does reduce() do?

              Combines elements into a single result using an associative function, e.g., stream.reduce(0, Integer::sum).

              ↑ Contents50

              Terminal Operations · continued

              Q140. What are the three forms of reduce?

              reduce(BinaryOperator) returns an Optional; reduce(identity, BinaryOperator) returns T; reduce(identity, accumulator, combiner) supports different result types and parallel combining.

              Q141. What is the identity value in reduce?

              A value that leaves other values unchanged under the operation (0 for addition, 1 for multiplication); it is the starting value and result for an empty stream.

              Q142. Why must reduce operations be associative?

              So that parallel execution can split and combine partial results in any grouping and still produce the same answer.

              Q143. What does count() do?

              Returns the number of elements as a long.

              Q144. What do min() and max() do?

              Return an Optional containing the smallest or largest element according to a Comparator.

                Parallel Streams and Performance

                KEY KNOWLEDGE

                • A parallel stream splits its source into chunks processed on the common ForkJoinPool and merges partial results. It pays off only for large, CPU-bound, stateless and associative work on splittable sources.

                Q181. What is a parallel stream?

                A stream that splits its source into chunks processed concurrently on multiple threads using the common ForkJoinPool.

                Q182. How do you create a parallel stream?

                collection.parallelStream() or stream.parallel().

                Q183. Which thread pool do parallel streams use by default?

                ForkJoinPool.commonPool(), shared across the JVM, which can cause contention if tasks are blocking or long-running.

                Q184. When should you use parallel streams?

                For large datasets with CPU-intensive, independent, stateless, and non-blocking operations on easily splittable sources like ArrayList or arrays.

                ↑ Contents62

                Parallel Streams and Performance · continued

                Q185. When should you avoid parallel streams?

                Small data sets, I/O or blocking operations, order-dependent logic, shared mutable state, or poorly splittable sources like LinkedList and Stream.iterate.

                Q186. Which data sources split well for parallelism?

                ArrayList, arrays, IntStream.range, and HashMap splitting reasonably; LinkedList and Stream.iterate split poorly.

                Q187. What are the thread-safety issues with parallel streams?

                Modifying shared non-thread-safe state (like adding to an ArrayList in forEach) causes race conditions. Use collectors, reductions, or concurrent structures.

                Q188. Does parallel stream preserve order?

                collect and forEachOrdered preserve encounter order for ordered sources; plain forEach does not.

                Q189. How can you control the parallelism level?

                Set -Djava.util.concurrent.ForkJoinPool.common.parallelism=N, or run the stream inside a custom ForkJoinPool (an implementation-dependent workaround).

                Q190. Why is stream() sometimes slower than a for loop?

                Stream pipelines add overhead (lambda calls, boxing, object allocation). For small collections or simple loops, a classic loop can be faster.

                Parallel Streams and Performance · continued

                Q191. What is the difference between sequential and parallel stream results for reduce?

                Results match only if the accumulator is associative, stateless, and the identity is valid; otherwise parallel results can differ.

                Q192. What are best practices for using the Stream API?

                Keep lambdas pure and short, avoid side effects, prefer primitive streams for numbers, avoid reusing streams, benchmark before parallelizing, and don't overuse streams for simple loops.
