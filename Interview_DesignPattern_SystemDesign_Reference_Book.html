Fundamentals and Design Principles

Q1. What is a design pattern?

A design pattern is a reusable, proven solution template to a commonly occurring problem in software

design. It is not finished code but a description of how to structure classes and objects so the solution

can be adapted to many situations.

Q2. Where do design patterns originate from?

They were popularised by the book "Design Patterns: Elements of Reusable Object-Oriented Software"

(1994) by Erich Gamma, Richard Helm, Ralph Johnson and John Vlissides, known as the Gang of Four

(GoF). The book catalogued 23 patterns, borrowing the idea from architect Christopher Alexander's

pattern language.

Q3. What are the three categories of GoF patterns?

Creational patterns deal with object creation, Structural patterns deal with composing classes and

objects into larger structures, and Behavioral patterns deal with communication and responsibility

assignment between objects.

Q4. What are the main benefits of using design patterns?

They provide a shared vocabulary for developers, capture proven best practices, improve code

reusability and maintainability, reduce design time, and make systems more flexible and easier to

extend.

Q5. How is a design pattern different from an algorithm?

An algorithm is a precise, step-by-step set of instructions that achieves a goal, whereas a pattern is a

higher-level blueprint describing structure and relationships. The same pattern can be implemented in

many ways in code.

Q6. How is a design pattern different from a framework or library?

A library is code you call, a framework is code that calls you (inversion of control) and provides a

skeleton application, while a pattern is only a conceptual solution. Frameworks often implement several

patterns internally.

Q7. What does SOLID stand for?

Single Responsibility, Open/Closed, Liskov Substitution, Interface Segregation and Dependency

Inversion. They are five object-oriented design principles that guide writing maintainable and extensible

code, and many patterns embody them.

Q8. Explain the Single Responsibility Principle (SRP).

A class should have only one reason to change, meaning it should own one cohesive responsibility. For

example, separate a class that calculates invoices from one that prints or persists them.

Q9. Explain the Open/Closed Principle (OCP).

Software entities should be open for extension but closed for modification. You add new behaviour by

adding new code (for example a new Strategy implementation) rather than editing tested existing code.

Q10. Explain the Liskov Substitution Principle (LSP).

Objects of a subclass must be usable wherever the base class is expected without breaking

correctness. The classic violation is Square extending Rectangle and breaking width/height

assumptions.

Q11. Explain the Interface Segregation Principle (ISP).

Clients should not be forced to depend on methods they do not use. Prefer several small, role-specific

interfaces over one large "fat" interface.

Q12. Explain the Dependency Inversion Principle (DIP).

High-level modules should not depend on low-level modules; both should depend on abstractions.

Abstractions should not depend on details, but details on abstractions. It is the basis of dependency

injection.

Q13. What does "favor composition over inheritance" mean?

Build behaviour by holding references to other objects (has-a) rather than extending base classes

(is-a). Composition is more flexible, avoids deep hierarchies, allows behaviour to change at runtime

and reduces tight coupling.

Q14. What does "program to an interface, not an implementation" mean?

Code should depend on abstract types (interfaces or abstract classes) rather than concrete classes, so

implementations can be swapped without changing clients. This enables polymorphism, testing with

mocks and loose coupling.

Q15. What are DRY, KISS and YAGNI?

DRY (Don't Repeat Yourself) avoids duplicated knowledge, KISS (Keep It Simple, Stupid) favours the

simplest workable design, and YAGNI (You Aren't Gonna Need It) discourages building features before

they are required. Over-applying patterns can violate KISS and YAGNI.

Creational Patterns

Q16. What is the Singleton pattern?

Singleton ensures a class has only one instance and provides a global access point to it. It is used for

shared resources such as configuration, logging or connection managers.

Q17. How do you implement a thread-safe Singleton?

Options include eager initialization, a synchronized getInstance(), double-checked locking with a

volatile field, the initialization-on-demand holder idiom, or an enum singleton in Java. The holder idiom

and enum are simple, lazy and thread-safe.

Q18. What is double-checked locking and why is volatile needed?

The instance is checked for null before and after acquiring a lock to avoid synchronizing every call.

Volatile prevents instruction reordering so another thread cannot see a partially constructed object.

Q19. What are the drawbacks of the Singleton pattern?

It introduces global state, hides dependencies, makes unit testing hard, can violate SRP, and can be

broken by reflection, serialization or multiple class loaders. Dependency injection with a singleton

scope is often preferred.

Q20. How can Singleton be broken and how do you prevent it?

Reflection can call the private constructor, serialization can create a new instance on deserialization,

and cloning can duplicate it. Prevent by throwing from the constructor if an instance exists,

implementing readResolve(), disabling clone, or using an enum singleton.

Q21. Why is an enum a good way to implement Singleton in Java?

The JVM guarantees enum values are instantiated once, thread-safely, and enums are protected

against reflection and serialization attacks. Joshua Bloch recommends it as the best singleton

approach.

Q22. What is the difference between a Singleton and a static class?

A singleton is a real object that can implement interfaces, be passed around, be lazily created and be

subclassed or mocked. A static class cannot implement interfaces polymorphically or hold instance

state, and is harder to test.

Q23. What is the difference between Singleton and a Spring singleton scope?

The GoF Singleton guarantees one instance per class loader through the class itself. A Spring

singleton bean is one instance per application context, managed by the container, and the class itself

may still be instantiated elsewhere.

Q24. What is the Factory Method pattern?

Factory Method defines an interface for creating an object but lets subclasses decide which concrete

class to instantiate. It defers instantiation to subclasses and decouples client code from concrete

products.

Q25. What is the difference between Simple Factory and Factory Method?

A Simple Factory is a single class with a method (often a switch) that returns different products and is

not a GoF pattern. Factory Method uses inheritance: each subclass overrides a creation method to

return its own product.

Q26. When should you use Factory Method?

Use it when a class cannot anticipate which objects it must create, when you want subclasses to

specify the created objects, or when you want to give library users a way to extend internal

components.

Q27. Give a real-world example of Factory Method.

In Java, Calendar.getInstance(), NumberFormat.getInstance() and Collection.iterator() are factory

methods. A logistics app with a createTransport() method overridden by RoadLogistics (Truck) and

SeaLogistics (Ship) is a textbook example.

Q28. What are the advantages and disadvantages of Factory Method?

It removes tight coupling to concrete products, follows SRP and OCP, and centralises creation code.

The downside is more classes and complexity because of the additional creator subclasses.

Q29. How does Factory Method relate to Template Method?

Factory Method is often called by a Template Method as one of its steps. The template defines the

algorithm skeleton while the factory method supplies the object that a step needs.

Q30. What is the Abstract Factory pattern?

Abstract Factory provides an interface for creating families of related or dependent objects without

specifying their concrete classes. For example, a GUIFactory that creates matching Button and

Checkbox for Windows or Mac.

Q31. What is the difference between Factory Method and Abstract Factory?

Factory Method creates one product through inheritance, whereas Abstract Factory creates a family of

related products through object composition. Abstract Factories are often implemented using several

factory methods.

Q32. When should you choose Abstract Factory?

Choose it when the system must be independent of how its products are created, when products must

be used together as a family, or when you want to expose only interfaces and not implementations.

Q33. What are the drawbacks of Abstract Factory?

Adding a new product type requires changing the abstract factory interface and every concrete factory.

The number of interfaces and classes grows quickly.

Q34. Give a real-world example of Abstract Factory.

Java's DocumentBuilderFactory and TransformerFactory, or a cross-platform UI toolkit and a database

access layer returning matching Connection, Command and Reader objects per vendor (ADO.NET

DbProviderFactory).

Q35. What is the Builder pattern?

Builder separates the construction of a complex object from its representation, letting the same

construction process create different representations. It builds objects step by step, usually with a fluent

interface.

Q36. What problem does Builder solve?

It solves the "telescoping constructor" problem where many optional parameters lead to constructors

with long parameter lists. Builder gives readable, named steps and supports immutable objects.

Q37. What is the role of the Director in Builder?

The Director defines the order in which construction steps are executed to produce a particular

configuration, while the Builder provides the implementations of those steps. Many modern fluent

builders skip the Director.

Q38. Give examples of Builder in standard libraries.

Java's StringBuilder, Stream.Builder, Locale.Builder, Lombok's @Builder, .NET's StringBuilder and

UriBuilder, and Protocol Buffers message builders.

Q39. How does Builder differ from Abstract Factory?

Builder constructs a complex object step by step and returns it at the end, focusing on one product.

Abstract Factory returns families of products immediately in a single call.

Q40. How does Builder help create immutable objects?

The builder accumulates mutable values, then build() passes them to a private constructor of the

immutable class, which validates and assigns final fields. The finished object has no setters and is

thread-safe.

Q41. What is the Prototype pattern?

Prototype creates new objects by copying (cloning) an existing instance instead of constructing from

scratch. It is useful when object creation is expensive or when the concrete class is only known at

runtime.

Q42. What is the difference between shallow copy and deep copy in Prototype?

A shallow copy duplicates the object but shares references to nested objects, while a deep copy

recursively duplicates nested objects so the clone is fully independent. Prototype usually requires deep

copies to avoid shared mutable state.

Q43. What are the problems with Java's Object.clone()?

Cloneable is a marker interface without a clone method, clone() is protected, it bypasses constructors,

makes shallow copies by default and has problems with final fields. Copy constructors, copy factories

or serialization are preferred.

Q44. When would you use Prototype over a factory?

Use it when classes to instantiate are specified at runtime, when initialization is costly (e.g. loaded from

a database), or when you want to avoid a parallel hierarchy of factories. A prototype registry holding

preconfigured instances is common.

Q45. Give a real-world example of Prototype.

JavaScript's prototypal inheritance and Object.create(), cell division in biology, copying a

pre-configured document template or a game enemy with preset stats, and Spring's prototype bean

scope.

Q46. What is the Object Pool pattern?

Object Pool keeps a set of initialized, reusable objects ready for use instead of creating and destroying

them on demand. It improves performance for expensive objects such as database connections or

threads.

Q47. What are the risks of using Object Pool?

Objects must be reset to a clean state before reuse, leaks occur if clients do not return them, pool

sizing is difficult, and shared state can cause concurrency bugs. Modern JVMs make pooling of cheap

objects counterproductive.

Q48. Give examples of Object Pool in practice.

JDBC connection pools such as HikariCP, thread pools via ExecutorService, Apache Commons Pool,

and the .NET ThreadPool and ArrayPool.

Q49. What is the Lazy Initialization pattern?

It delays creation of an object or computation of a value until it is first needed. It saves resources if the

object is never used, but needs care to remain thread-safe.

Q50. What is Dependency Injection and how does it relate to creational patterns?

Dependency Injection supplies an object's dependencies from outside instead of the object creating

them with new. It replaces many Singleton and Factory usages by letting a container control creation

and lifetime.

Structural Patterns

Q51. What is the Adapter pattern?

Adapter converts the interface of a class into another interface that clients expect, letting incompatible

classes work together. It acts like a power plug adapter between two incompatible sockets.

Q52. What is the difference between class adapter and object adapter?

A class adapter uses inheritance (multiple inheritance or extending the adaptee), while an object

adapter uses composition by holding a reference to the adaptee. Object adapters are more flexible and

are preferred in Java.

Q53. When should you use the Adapter pattern?

Use it when integrating legacy or third-party code with an incompatible interface, when you want to

reuse existing classes, or to normalise multiple external APIs behind one internal interface.

Q54. Give examples of Adapter in standard libraries.

Arrays.asList(), InputStreamReader (adapts InputStream to Reader), Collections.enumeration(), and

wrapper classes around payment gateway SDKs.

Q55. How does Adapter differ from Facade?

Adapter changes one interface to match another, typically wrapping a single class. Facade defines a

new, simpler interface to an entire subsystem of many classes.

Q56. How does Adapter differ from Decorator and Proxy?

Adapter changes the interface of the wrapped object, Decorator keeps the same interface while adding

behaviour, and Proxy keeps the same interface while controlling access to the object.

Q57. What is the Bridge pattern?

Bridge decouples an abstraction from its implementation so that the two can vary independently. It

splits a class hierarchy into two separate hierarchies connected by composition.

Q58. What problem does Bridge solve?

It prevents the combinatorial explosion of subclasses, for example Shape x Color or RemoteControl x

Device, by separating the dimensions into abstraction and implementor hierarchies.

Q59. What is the difference between Bridge and Adapter?

Bridge is designed up front to let abstraction and implementation evolve independently, while Adapter

is applied after the fact to make existing incompatible classes work together.

Q60. What is the difference between Bridge and Strategy?

Structurally they look similar, but Strategy focuses on swapping a single algorithm for behaviour, while

Bridge is a structural separation of a whole abstraction hierarchy from an implementation hierarchy.

Q61. Give a real-world example of Bridge.

JDBC (the Driver interface bridges applications and vendor drivers), SLF4J over logging back ends,

and GUI toolkits separating window abstractions from platform-specific rendering.

Q62. When is the Bridge pattern not appropriate?

When there is only one implementation or one dimension of variation, because it adds indirection and

complexity without benefit.

Q63. What is the Composite pattern?

Composite composes objects into tree structures to represent part-whole hierarchies and lets clients

treat individual objects and compositions uniformly through a common interface.

Q64. What are the participants in Composite?

Component (common interface), Leaf (no children, does real work), Composite (stores children and

delegates operations to them), and Client (works through the Component interface).

Q65. Give real-world examples of Composite.

File systems (files and folders), GUI widget trees, organisation hierarchies, HTML/DOM nodes, and

menus with sub-menus.

Q66. What is the trade-off between transparency and safety in Composite?

Placing add/remove child methods in the Component gives transparency (uniform treatment) but leaf

classes get meaningless operations. Placing them only in Composite is safer but clients must

distinguish leaves from composites.

Q67. How does Composite relate to Iterator and Visitor?

Iterator is used to traverse a Composite tree, and Visitor can apply an operation across all nodes of the

tree without changing node classes.

Q68. What are the drawbacks of Composite?

It can make the design overly general, making it hard to restrict the types of components in a

composite, and recursive operations on deep trees may have performance and stack-depth

implications.

Q69. What is the Decorator pattern?

Decorator attaches additional responsibilities to an object dynamically by wrapping it in decorator

objects that implement the same interface. It is a flexible alternative to subclassing for extending

behaviour.

Q71. How is Decorator different from inheritance?

Inheritance adds behaviour statically at compile time to all instances of a class, while Decorator adds

behaviour at runtime to individual objects and can combine multiple behaviours in any order.

Q72. What are the disadvantages of Decorator?

It creates many small objects, the order of wrapping can matter, debugging nested wrappers is harder,

and identity checks fail because the decorator is not the original object.

Q73. How does Decorator differ from Proxy?

Both wrap an object with the same interface. Decorator adds responsibilities and is usually composed

by the client, while Proxy controls access and usually manages the lifecycle of the real subject itself.

Q74. Give a coffee shop example of Decorator.

A Beverage interface with Espresso as the concrete component, and decorators like Milk, Mocha and

Whip that wrap a beverage and add to cost() and description(). Customers can stack decorators in any

order.

Q75. How does Decorator support the Open/Closed Principle?

New behaviours are added by writing new decorator classes without changing the existing component

or other decorators.

Q76. What is the Facade pattern?

Facade provides a unified, simplified interface to a set of interfaces in a subsystem, making the

subsystem easier to use. It does not prevent access to underlying classes but hides their complexity.

Q77. When should you use Facade?

Use it to provide a simple entry point to a complex library, to layer a system, to decouple clients from

subsystem details, or to wrap legacy code.

Q78. Give real-world examples of Facade.

A HomeTheaterFacade with watchMovie(), a service layer exposing placeOrder() that coordinates

inventory, payment and shipping, and libraries such as jQuery or SLF4J.

Q79. What is the risk of Facade becoming a "god object"?

If the facade accumulates too much logic and responsibilities it becomes tightly coupled to everything

and violates SRP. Keep it a thin delegating layer, possibly with multiple facades.

Q80. How does Facade differ from Mediator?

Facade is a one-way simplification for clients and the subsystem is unaware of it. Mediator coordinates

two-way communication between peer components that know about the mediator.

Q81. What is the Flyweight pattern?

Flyweight minimises memory use by sharing as much data as possible among many similar objects. It

separates intrinsic (shared, immutable) state from extrinsic (context-specific) state.

Q82. What are intrinsic and extrinsic state in Flyweight?

Intrinsic state is stored inside the flyweight and is independent of context, such as a character glyph or

tree texture. Extrinsic state depends on context and is passed in by the client, such as position or

colour.

Q83. Give real-world examples of Flyweight.

Java's String intern pool, Integer.valueOf() cache for -128..127, glyph objects in text editors,

tree/particle objects in games, and map tile rendering.

Q84. What is a FlyweightFactory?

A factory that maintains a pool of flyweights keyed by intrinsic state, returning an existing instance if

present or creating one otherwise, so clients never instantiate flyweights directly.

Q85. When should Flyweight be used?

When an application uses a very large number of objects, storage cost is high, most state can be made

extrinsic, and object identity is not important.

Q86. What are the trade-offs of Flyweight?

It saves memory but costs CPU time to compute or pass extrinsic state, and increases code

complexity. Flyweights must be immutable to be safely shared.

Q87. What is the Proxy pattern?

Proxy provides a surrogate or placeholder for another object to control access to it. It implements the

same interface as the real subject.

Q88. What are the types of proxies?

Virtual proxy (lazy creation of expensive objects), Remote proxy (local representative of a remote

object), Protection proxy (access control), Caching proxy, Smart reference proxy (reference counting,

logging) and Firewall proxy.

Q89. Give real-world examples of Proxy.

Java RMI stubs, java.lang.reflect.Proxy, Spring AOP and Hibernate lazy-loading proxies, Nginx as a

reverse proxy, and image placeholders that load on demand.

Q90. What is the difference between static and dynamic proxy?

A static proxy is a hand-written class compiled ahead of time for one interface. A dynamic proxy is

generated at runtime (JDK Proxy, CGLIB, ByteBuddy) and can serve any interface, enabling

cross-cutting concerns like logging and transactions.

Q91. How does a JDK dynamic proxy differ from CGLIB?

JDK proxies require the target to implement an interface and use reflection through InvocationHandler.

CGLIB generates a subclass of the target at runtime so it works for classes without interfaces, but

cannot proxy final classes or methods.

Q92. How does Proxy differ from Facade and Adapter?

Proxy has the same interface as the real object and controls access, Adapter converts one interface to

another, and Facade simplifies a subsystem with a new interface.

Behavioral Patterns

Q93. What is the Strategy pattern?

Strategy defines a family of algorithms, encapsulates each one and makes them interchangeable at

runtime. The context holds a reference to a strategy interface and delegates the work to it.

Q94. Give examples of Strategy.

Comparator passed to Collections.sort(), payment methods (card, UPI, PayPal), compression

algorithms, route-calculation strategies in a map app, and Spring's pluggable PasswordEncoder.

Q95. How does Strategy replace conditional statements?

Instead of a large if/else or switch selecting an algorithm, each branch becomes a strategy class, and

the context uses the chosen one polymorphically. This follows OCP because new strategies are added

without changing the context.

Q96. What is the difference between Strategy and State?

Both use composition and delegation. In Strategy the client typically chooses the algorithm and

strategies are independent. In State the object changes its own state objects as it transitions, and

states often know about each other.

Q97. What is the difference between Strategy and Template Method?

Template Method uses inheritance to vary parts of an algorithm and is fixed at compile time. Strategy

uses composition to swap the whole algorithm at runtime.

Q98. How can Strategy be implemented using lambdas?

When a strategy interface has a single method (a functional interface), a lambda or method reference

can replace a concrete class, e.g. list.sort((a, b) -> a.age - b.age).

Q99. What is the Observer pattern?

Observer defines a one-to-many dependency so that when one object (the subject) changes state, all

its dependents (observers) are notified and updated automatically.

Q100. What are push and pull models in Observer?

In the push model the subject sends detailed data to observers in the notification. In the pull model the

subject only notifies and observers query the subject for the data they need.

Q101. What are the problems with Observer?

Memory leaks from forgotten subscriptions (the lapsed listener problem), unpredictable notification

order, cascading updates, performance issues with many observers, and potential threading issues.

Q102. Give real-world examples of Observer.

Event listeners in GUI frameworks, JavaScript addEventListener, RxJava and Reactor, Java's

PropertyChangeListener, Spring ApplicationEvent, and publish-subscribe messaging systems.

Q103. How is Observer different from Publish-Subscribe?

In Observer, subjects and observers know each other directly. In Pub/Sub a message broker or event

channel sits between publishers and subscribers so they are fully decoupled, often across processes.

Q104. Why were java.util.Observable and Observer deprecated?

Observable is a class (forcing inheritance), its setChanged() is protected, it is not serializable and not

thread-safe in an ordered way, and the notification payload is untyped. java.beans listeners or Flow API

are preferred.

Q105. How do you make Observer thread-safe?

Use a CopyOnWriteArrayList for observers, notify on a snapshot, avoid holding locks while calling

observers, and consider dispatching notifications asynchronously on an executor.

Q106. What is the Command pattern?

Command encapsulates a request as an object, letting you parameterize clients with different requests,

queue or log requests and support undoable operations.

Q107. What are the participants in Command?

Command (interface with execute), ConcreteCommand (binds a receiver and action), Receiver (does

the work), Invoker (triggers the command), and Client (creates and configures commands).

Q108. How do you implement undo/redo using Command?

Each command implements execute() and undo(), and the invoker keeps a history stack of executed

commands. Undo pops and calls undo(), while redo uses a second stack.

Q109. Give real-world examples of Command.

Menu items and toolbar buttons in editors, Runnable submitted to an executor, job queues, macro

recording, database transaction logs, and remote controls.

Q110. What is a macro command?

A composite command that holds a list of other commands and executes them in sequence, enabling

macros and batch operations.

Q111. How does Command differ from Strategy?

Command encapsulates a request or action (what to do, often with receiver and parameters, possibly

undoable), whereas Strategy encapsulates an interchangeable algorithm used to perform a single task

in different ways.

Q112. What is the State pattern?

State allows an object to alter its behaviour when its internal state changes, appearing to change its

class. Each state is a class encapsulating state-specific behaviour.

Q113. Give an example use case for State.

A vending machine (NoCoin, HasCoin, Sold, SoldOut), an order lifecycle (New, Paid, Shipped,

Delivered, Cancelled), TCP connection states, or a media player (Playing, Paused, Stopped).

Q114. Who is responsible for state transitions in State pattern?

Either the context (centralised, simpler) or the concrete states (decentralised, more flexible but states

become coupled). Choosing states to trigger transitions reduces conditional logic in the context.

Q115. How does State help eliminate large conditionals?

Instead of every method checking a status flag with switch statements, each state class implements the

behaviour for that state, so the context just delegates to the current state object.

Q116. Should state objects be shared (Singleton/Flyweight)?

If states hold no instance data and are stateless, one shared instance each can be reused. If they store

context-specific data, a new instance per context is needed.

Q117. What is the Template Method pattern?

Template Method defines the skeleton of an algorithm in a base class method and lets subclasses

override specific steps without changing the algorithm's structure.

Q118. What are hooks in Template Method?

Hooks are optional methods with default (often empty) implementations in the base class that

subclasses may override to plug into the algorithm at specific points.

Q119. What is the Hollywood Principle?

"Don't call us, we'll call you." In Template Method the high-level base class calls the low-level subclass

methods, not the other way around. It underlies frameworks and inversion of control.

Q121. Why should the template method be final?

Making the skeleton final prevents subclasses from changing the algorithm's order and structure, which

is the whole point of the pattern; only the steps should be overridable.

Q122. What is the Iterator pattern?

Iterator provides a way to access the elements of an aggregate object sequentially without exposing its

underlying representation.

Q123. What is the difference between Iterator and Iterable in Java?

Iterable is an object that can produce an Iterator through iterator() and is what enables the for-each

loop. Iterator holds the traversal state with hasNext(), next() and optionally remove().

Q124. What is a fail-fast iterator?

An iterator that throws ConcurrentModificationException if the underlying collection is structurally

modified during iteration, detecting it using a modCount. Fail-safe iterators such as those of

CopyOnWriteArrayList iterate on a snapshot.

Q125. What are external versus internal iterators?

External iterators are controlled by the client who calls next() explicitly. Internal iterators take a function

and apply it to each element (forEach, stream), controlling the iteration themselves.

Q126. How does Iterator support SRP?

It moves traversal logic out of the collection into a separate object, so collections focus on storing data

and multiple traversals (forward, reverse, filtered) can exist independently.

Q127. What is the Mediator pattern?

Mediator defines an object that encapsulates how a set of objects interact, promoting loose coupling by

preventing objects from referring to each other explicitly.

Q128. Give real-world examples of Mediator.

An air traffic control tower, a chat room server, dialog boxes where a controller coordinates widgets,

Spring MVC's DispatcherServlet, and message buses.

Q129. What is the main risk of Mediator?

The mediator can become a monolithic "god object" containing too much coordination logic that is hard

to maintain.

Q130. How does Mediator differ from Observer?

Observer distributes communication through subject-observer subscriptions in a one-to-many way.

Mediator centralises many-to-many communication in one object that knows all the colleagues.

Q131. What is the Chain of Responsibility pattern?

It passes a request along a chain of handlers, where each handler decides either to process the

request or pass it to the next handler, decoupling sender from receiver.

Q132. Give real-world examples of Chain of Responsibility.

Servlet filters and middleware pipelines (Express, ASP.NET), Spring Security filter chain, logging levels

in Log4j, exception handling try/catch propagation, and approval workflows.

Q133. What happens if no handler processes the request in the chain?

The request may go unhandled, so you should provide a default or terminal handler, or define clear

behaviour such as throwing an exception or returning a default result.

Q134. How does Chain of Responsibility differ from Decorator?

Handlers in a chain may stop propagation and handle the request independently, while decorators

always delegate and add behaviour around a call. A chain focuses on who handles, while Decorator

focuses on extending behaviour.

Q135. What are the pros and cons of Chain of Responsibility?

It reduces coupling, allows reordering handlers and follows OCP. The cons are no guarantee that a

request is handled and difficult debugging when the chain is long.

Q136. What is the Visitor pattern?

Visitor lets you add new operations to an object structure without modifying the classes of the elements,

by moving the operation into a separate visitor class and using double dispatch.

Q137. What is double dispatch?

The method executed depends on the runtime type of two objects: the element calls visitor.visit(this),

so both the element type and visitor type determine the code that runs. It works around languages'

single dispatch.

Q138. What is the main drawback of Visitor?

Adding a new element class requires changing the visitor interface and all concrete visitors, so Visitor is

best when the element hierarchy is stable but operations change frequently.

Q139. Give real-world examples of Visitor.

Compiler AST traversal for type checking and code generation, Java's FileVisitor / Files.walkFileTree,

ASM bytecode visitors, and tax calculation across different item types.

Q140. How does Visitor relate to the Open/Closed Principle?

Visitor makes it easy to add new operations (open for extension) without modifying element classes,

but it makes adding new element types hard, so it is open in one dimension and closed in another.

Q141. What is the Memento pattern?

Memento captures and externalizes an object's internal state without violating encapsulation so that the

object can be restored to that state later.

Q142. What are the roles in Memento?

Originator (creates snapshots and restores from them), Memento (the immutable state holder) and

Caretaker (stores mementos but never inspects them).

Q143. How is Memento used for undo?

Before a change, the caretaker asks the originator for a memento and pushes it on a stack. Undo pops

the stack and tells the originator to restore from it.

Q144. What are the drawbacks of Memento?

Storing many snapshots can consume lots of memory, deep copies can be expensive, and the

caretaker must manage memento lifecycles. Incremental or delta snapshots, or Command-based undo,

can mitigate this.

Q145. What is the Interpreter pattern?

Interpreter defines a grammar for a language as a class hierarchy and an interpreter that uses the

representation to evaluate sentences in that language.

Q146. When should Interpreter be used?

For simple, stable grammars such as expression evaluators, rule engines, regex, SQL-like filters or

configuration DSLs. For complex grammars, parser generators like ANTLR are better.

Architectural and Enterprise Patterns

Q148. What is the MVC pattern?

Model-View-Controller separates an application into Model (data and business logic), View

(presentation) and Controller (handles input and updates model and view). It enables separation of

concerns and parallel development.

Q149. What is the difference between MVC, MVP and MVVM?

In MVC the controller handles input and the view may observe the model. In MVP the Presenter

mediates everything and the view is passive. In MVVM a ViewModel exposes bindable state and

commands, and data binding syncs it with the view.

Q150. What is the Repository pattern?

Repository mediates between the domain and data-mapping layers using a collection-like interface for

accessing domain objects, hiding persistence details from business logic.

Q151. What is the Unit of Work pattern?

Unit of Work tracks changes to objects during a business transaction and coordinates writing them out

as a single atomic transaction. JPA's EntityManager and Hibernate Session are examples.

Q152. What is the Data Access Object (DAO) pattern?

DAO abstracts and encapsulates all access to a data source, providing CRUD operations for a specific

entity so business logic is independent of storage technology.

Q153. What is the difference between Repository and DAO?

A DAO is closer to the database and table-oriented, while a Repository is domain-oriented, expressing

queries in terms of aggregates and domain language and acting like an in-memory collection.

Q154. What is Dependency Injection and what are its types?

DI is a technique where an object receives its dependencies from an external source. Types are

constructor injection (preferred), setter injection and interface/field injection.

Q155. What is the difference between Dependency Injection and Service Locator?

With DI the dependencies are pushed into the class, making them explicit. With Service Locator the

class pulls dependencies from a registry, hiding them and making testing harder.

Q156. What is the Inversion of Control (IoC) principle?

IoC means control flow and object creation are handed to a framework or container instead of being

controlled by application code. DI is one way to implement IoC.

Q157. What is the Data Transfer Object (DTO) pattern?

A DTO is a simple object that carries data between processes or layers, reducing the number of calls

and decoupling internal domain models from external API contracts.

Q158. What is the Specification pattern?

It encapsulates business rules as combinable objects (with and, or, not) that test whether an object

satisfies a criterion, useful for validation, selection and query building.

Q159. What is the Active Record pattern?

An object wraps a database row and includes both data and persistence/domain logic (save, find). It is

simple, used in Rails and Laravel, but couples domain objects to the schema.

Q160. What is the Data Mapper pattern?

A mapper layer moves data between objects and the database while keeping them independent of

each other. Hibernate/JPA are implementations, giving cleaner domain models than Active Record.

Q161. What is the CQRS pattern?

Command Query Responsibility Segregation uses separate models for updating information

(commands) and reading information (queries), allowing each side to be optimised and scaled

independently.

Q162. What is Event Sourcing?

coordinator.

Q165. What are the API Gateway and Backend-for-Frontend patterns?

An API Gateway is a single entry point that routes, authenticates and aggregates calls to

microservices. Backend-for-Frontend creates a tailored gateway per client type such as mobile or web.

Concurrency and Modern Patterns

Q166. What is the Producer-Consumer pattern?

Producers put work items in a shared queue and consumers take items from it, decoupling production

and consumption rates. In Java a BlockingQueue handles synchronisation.

Q167. What is the Thread Pool pattern?

A fixed or dynamic set of reusable worker threads executes submitted tasks from a queue, avoiding the

cost of creating a thread per task and bounding resource usage (ExecutorService).

Q168. What is the Reactor pattern?

A single-threaded event loop demultiplexes I/O events and dispatches them to handlers. It is the base

of Netty, Node.js and Nginx for scalable non-blocking I/O.

Q169. What is the Future/Promise pattern?

A Future represents the result of an asynchronous computation that will be available later, allowing

callers to continue working and retrieve or compose the result when ready (CompletableFuture,

JavaScript Promise).

Q170. What is the Read-Write Lock pattern?

It allows many concurrent readers or a single exclusive writer, improving throughput for read-heavy

shared data (ReentrantReadWriteLock, StampedLock).

Q171. What is the Monitor Object pattern?

It synchronises method execution so only one thread runs inside an object at a time, using condition

variables for waiting and signalling. Java's synchronized, wait() and notify() implement it.

Q172. What is the Immutable Object pattern and why does it help concurrency?

An immutable object's state cannot change after construction, so it can be shared across threads

without synchronization. String and java.time classes are examples.

Q173. What is the Active Object pattern?

It decouples method invocation from execution by turning calls into requests queued to a scheduler

thread, giving each object its own thread of control. Actor frameworks like Akka are related.

Q174. What is the Bulkhead pattern?

It isolates resources (thread pools, connections) per component so failure or overload in one part

cannot exhaust resources for the whole system, like watertight compartments in a ship.

Q175. What is the Retry pattern and what should you consider?

It re-attempts a failed operation that is likely transient. Use exponential backoff with jitter, a maximum

number of attempts, and only for idempotent operations to avoid overloading or duplicating side effects.

Q176. What is the Null Object pattern?

It provides an object with neutral, do-nothing behaviour in place of null, so clients need no null checks.

Collections.emptyList() and Optional-like defaults are examples.

Q177. What is the Dependency Injection container's role in modern patterns like the Registry

and Plugin?

The container wires and manages lifecycle of components, enabling Plugin architectures where

implementations are discovered and registered at runtime (ServiceLoader, Spring beans) without

changing client code.

Anti-Patterns, Comparisons and Scenarios

Q178. What is an anti-pattern?

An anti-pattern is a commonly used but ineffective or counterproductive solution to a recurring problem,

such as God Object, Spaghetti Code or Golden Hammer.

Q179. What is the God Object anti-pattern?

A class that knows or does too much and holds many unrelated responsibilities. Fix it by applying SRP

and extracting cohesive classes.

Q180. What is the Golden Hammer anti-pattern?

Over-reliance on a familiar tool or pattern for every problem, e.g. forcing Singleton or microservices

everywhere because they worked before.

Q181. What is Spaghetti Code and Lava Flow?

Spaghetti Code has tangled control flow and no structure. Lava Flow is dead or poorly understood code

that stays because nobody dares remove it. Refactoring and tests help remove both.

Q182. What is the Service Locator anti-pattern debate?

Critics say it hides dependencies, hurts testability and creates runtime failures. Supporters say it is

acceptable in some plugin scenarios; DI is usually preferred.

Q183. What is over-engineering with patterns and how do you avoid it?

Applying patterns where simple code suffices adds needless abstraction. Introduce a pattern when you

feel real pain such as duplication or rigid change, and refactor towards patterns incrementally.

Q184. Which pattern would you use to add logging, caching and security to a service without

altering it?

Decorator or Proxy (and AOP in frameworks). Both wrap the service with the same interface, keeping

cross-cutting concerns out of business code.

Q185. Which pattern would you use to support multiple payment gateways?

Strategy (or Adapter) for interchangeable payment processors behind a PaymentGateway interface,

plus a Factory to select the right implementation by configuration.

Q186. Which pattern would you use for a notification system sending email, SMS and push?

Factory or Abstract Factory to create channel senders, Strategy to select the channel, and Observer or

Pub/Sub to trigger notifications from domain events.

Q187. How would you design an undo feature in a text editor?

Use Command with a history stack for operation-based undo, or Memento for snapshot-based undo.

Combine with Composite (macro commands) for grouped actions.

Q188. Which pattern fits a plugin architecture?

Strategy/Factory with a registry and service-loader discovery, often combined with Observer for

lifecycle events and Facade for exposing a stable host API.

Q189. How would you integrate a third-party library with an incompatible API?

Wrap it in an Adapter that implements your own interface, isolating the rest of your code from the

vendor API so it can be replaced later.

Q190. How would you build a complex SQL or HTTP request object with many optional

parameters?

Use the Builder pattern with a fluent interface and validation in build(), which also produces an

immutable request object.

All wrap objects. Decorator adds behaviour on the same interface, Proxy controls access on the same

Q197. Which patterns help achieve loose coupling?

Observer, Mediator, Strategy, Factory, Abstract Factory, Bridge and Dependency Injection all reduce

deep hierarchies.

easier extension or better testability.

System Design Fundamentals and Estimation

Q1. What is system design and what does an interviewer look for?

System design is defining the architecture, components, data flow and trade-offs of a system to meet

functional and non-functional requirements. Interviewers look for requirement clarification, structured

thinking, sound trade-off analysis, scalability and reliability awareness, and clear communication.

Q2. What framework can you follow to answer a system design question?

Clarify requirements and scope, estimate scale, define APIs and data model, sketch a high-level

design, deep-dive into critical components, then discuss bottlenecks, trade-offs, failure handling and

future improvements.

Q3. What is the difference between functional and non-functional requirements?

Functional requirements describe what the system does (features such as posting a tweet).

Non-functional requirements describe qualities such as scalability, latency, availability, consistency,

durability, security and cost.

Q4. What is the difference between latency, throughput and bandwidth?

Latency is the time to complete one request, throughput is the number of requests or operations

completed per unit time, and bandwidth is the maximum data transfer capacity of a link.

Q5. What is availability and how is it measured?

Availability is the percentage of time a system is operational, usually expressed in nines: 99.9% allows

about 8.76 hours of downtime a year, 99.99% about 52 minutes, and 99.999% about 5 minutes.

Q6. What is the difference between reliability and availability?

Reliability is the probability a system performs correctly over a period of time without failure, while

availability is the fraction of time it is up and able to serve requests. A system can be available but

unreliable if it returns wrong results.

Q7. What is scalability and what are its types?

Scalability is the ability to handle increased load by adding resources. Vertical scaling (scale up) adds

power to a machine, while horizontal scaling (scale out) adds more machines.

Q8. What is back-of-the-envelope estimation and why is it important?

It is quick approximate calculation of traffic, storage, bandwidth and memory using round numbers. It

validates whether a design is feasible and drives decisions on sharding, caching and hardware.

Q9. How do you estimate QPS from daily active users?

QPS = (DAU x actions per user per day) / 86,400 seconds. For example 10 million DAU doing 10

requests each gives about 1,157 average QPS, and peak is often 2 to 5 times the average.

Q10. How do you estimate storage needs?

Multiply the number of records created per day by the average record size and by the retention period,

then add replication factor and overhead. For example 100 million 1 KB records a day is about 100 GB

a day, or roughly 36.5 TB a year before replication.

Q11. What latency numbers should every engineer know?

Roughly: L1 cache 1 ns, main memory 100 ns, SSD random read 100 microseconds, network round

trip within a data centre 0.5 ms, disk seek 10 ms and cross-continent round trip 150 ms. Memory is

about 100x faster than SSD and SSD about 100x faster than disk seek.

Q12. What are SLI, SLO and SLA?

An SLI is a measured indicator such as request latency or error rate, an SLO is the target for that

indicator (for example 99.9% of requests under 300 ms), and an SLA is a contractual agreement with

penalties if the target is missed.

Scalability, Load Balancing and Networking

Q16. What is a load balancer and why is it used?

A load balancer distributes incoming traffic across multiple servers to improve availability, throughput

and fault tolerance. It also performs health checks, TLS termination and can enable zero-downtime

deployments.

Q17. What are common load-balancing algorithms?

Round robin, weighted round robin, least connections, least response time, IP hash and consistent

hashing. Choice depends on server homogeneity and whether session affinity is needed.

Q18. What is the difference between Layer 4 and Layer 7 load balancing?

L4 balances based on IP and TCP/UDP ports and is fast and simple. L7 inspects HTTP content (URL,

headers, cookies), enabling content-based routing, SSL termination and finer control at higher

processing cost.

Q19. What are sticky sessions and what are the alternatives?

Sticky sessions route a user's requests to the same server using cookies or IP hash. This hurts balance

and failover, so a better alternative is stateless servers with session data in a shared store like Redis or

in signed tokens (JWT).

Q20. What is the difference between stateful and stateless services?

Stateless services keep no client state between requests, so any instance can handle any request and

scaling is easy. Stateful services hold state locally and require routing, replication or state migration.

Q21. How do you avoid the load balancer being a single point of failure?

Run multiple load balancers in active-passive or active-active pairs with a floating virtual IP, DNS-based

balancing, or anycast, and use managed cloud load balancers that are redundant across zones.

Q22. What is consistent hashing and why is it used?

Consistent hashing maps servers and keys onto a hash ring so that adding or removing a node remaps

only about K/N keys instead of nearly all. Virtual nodes smooth out the distribution. It is used in caches,

DynamoDB and Cassandra.

Q23. What is a reverse proxy and how does it differ from a forward proxy?

A reverse proxy sits in front of servers, handling client requests for load balancing, caching, TLS and

security (Nginx, HAProxy). A forward proxy sits in front of clients and hides client identity or filters

outbound traffic.

Q24. What is DNS and how can it be used for scalability?

DNS maps domain names to IP addresses. It enables geo-DNS and latency-based routing to the

nearest data centre, round-robin distribution and failover, though caching and TTLs delay changes.

Q25. What is auto-scaling and what metrics trigger it?

Auto-scaling automatically adds or removes instances based on metrics such as CPU, memory,

request rate, queue depth or custom metrics, or on schedules. It needs stateless services, fast startup

and cooldown periods to avoid thrashing.

Q26. What is the difference between HTTP/1.1, HTTP/2 and HTTP/3?

HTTP/1.1 uses one request per connection at a time, HTTP/2 multiplexes streams over a single TCP

connection with header compression, and HTTP/3 runs over QUIC (UDP) to remove TCP head-of-line

blocking and speed up connection setup.

Caching and Content Delivery

Q31. Why do we use caching?

Caching stores frequently accessed data in a faster layer to reduce latency, database load and cost,

improving throughput and user experience.

Q32. What are the main caching strategies?

Cache-aside (lazy loading), read-through, write-through, write-behind (write-back) and write-around.

They differ in who populates the cache and when writes reach the database.

Q33. Explain cache-aside.

The application checks the cache first; on a miss it reads from the database, stores the result in the

cache and returns it. Writes go to the database and invalidate or update the cache. It is simple and

resilient to cache failure but can serve stale data.

Q34. Explain write-through versus write-back caching.

Write-through writes to the cache and database synchronously, giving consistency with higher write

latency. Write-back writes to the cache first and flushes to the database asynchronously, giving low

latency but risking data loss if the cache fails.

Q35. What are cache eviction policies?

LRU (least recently used), LFU (least frequently used), FIFO, random and TTL-based expiry. LRU is

the most common general-purpose choice; LFU suits stable hot-key workloads.

Q36. How would you implement an LRU cache?

Use a hash map for O(1) lookup combined with a doubly linked list that keeps usage order; on access

move the node to the head and on eviction remove the tail. This gives O(1) get and put.

Q37. What is cache invalidation and why is it hard?

It is removing or updating cached entries when the source data changes. It is hard because of race

conditions, distributed caches and the need to balance freshness against hit rate. Approaches are

TTLs, event-based invalidation and versioned keys.

Q38. What is a cache stampede (thundering herd) and how do you prevent it?

When a popular key expires, many requests simultaneously hit the database to rebuild it. Prevent with

request coalescing/locking, probabilistic early refresh, staggered TTL with jitter, and serving

stale-while-revalidate.

Q39. What is cache penetration and how do you handle it?

Requests for keys that do not exist bypass the cache and hit the database every time, often

maliciously. Mitigate by caching null results with a short TTL, using Bloom filters, and validating input.

Q40. What is a hot key problem in caching?

A single key receiving disproportionate traffic overloads one cache node. Solutions include local

in-process caching, replicating hot keys across nodes, key suffix sharding and request coalescing.

Q41. What is the difference between Redis and Memcached?

Memcached is a simple multi-threaded in-memory key-value cache. Redis supports rich data structures

(lists, sets, sorted sets, streams), persistence, replication, clustering, pub/sub and Lua scripting, so it is

used for more than caching.

Q42. Where can caching occur in a system?

Browser, CDN, API gateway, application (in-process), distributed cache, database buffer pool and OS

page cache. Layered caching reduces latency at each hop.

Q43. What is a CDN and how does it work?

A Content Delivery Network is a geographically distributed network of edge servers that cache content

close to users, reducing latency and origin load. Requests are routed using DNS or anycast to the

nearest edge.

Q44. What is the difference between push and pull CDNs?

In a pull CDN content is fetched from the origin on first request and cached. In a push CDN you upload

content to the CDN ahead of time, which suits small, infrequently changing sites but needs more

management.

Q45. How do you invalidate content in a CDN?

Use cache-control headers and TTLs, versioned or hashed file names (cache busting), and explicit

purge or invalidation API calls for urgent changes.

Q46. What HTTP headers control caching?

Cache-Control (max-age, no-cache, no-store, private, public), ETag and If-None-Match, Last-Modified

and If-Modified-Since, and Expires. They enable conditional requests and validation.

Q47. How do you measure cache effectiveness?

Hit ratio, miss ratio, eviction rate, latency percentiles, memory usage and backend load reduction. A low

hit ratio suggests wrong keys, TTLs or cache size.

Databases, Storage and Data Modelling

Q48. How do you choose between SQL and NoSQL databases?

Choose SQL for structured data, strong consistency, complex joins and transactions. Choose NoSQL

for flexible schemas, massive horizontal scale, high write throughput or specific data models

(key-value, document, wide-column, graph).

Q49. What are ACID properties?

Atomicity (all or nothing), Consistency (valid state transitions), Isolation (concurrent transactions do not

interfere) and Durability (committed data survives failures).

Q50. What is BASE?

Basically Available, Soft state, Eventually consistent: a model used by many NoSQL systems that

favours availability and scalability over immediate consistency.

Q51. What are the transaction isolation levels?

Read Uncommitted, Read Committed, Repeatable Read and Serializable. Higher levels prevent dirty

reads, non-repeatable reads and phantom reads but reduce concurrency.

Q52. What is database indexing and how does it work?

An index is a data structure (commonly a B-tree or B+tree) that allows fast lookups without scanning

the whole table, at the cost of extra storage and slower writes.

Q53. What is the difference between a clustered and a non-clustered index?

A clustered index defines the physical order of rows in the table (only one per table). A non-clustered

index is a separate structure storing key values with pointers to the rows.

Q54. What are B-tree and LSM-tree storage engines?

B-trees update pages in place and give predictable reads, used by MySQL InnoDB and PostgreSQL.

LSM-trees buffer writes in memory and merge sorted files in the background, giving high write

throughput, used by Cassandra, RocksDB and HBase.

Q55. What is a composite index and the leftmost prefix rule?

A composite index covers multiple columns in order, and it can serve queries filtering on a leftmost

prefix of those columns. An index on (a, b, c) supports a, a+b and a+b+c but not b alone.

Q56. What is database replication and what types exist?

Replication copies data across nodes for availability and read scaling. Types include leader-follower

(primary-replica), multi-leader and leaderless, with synchronous or asynchronous propagation.

Q57. What is replication lag and how do you handle it?

Followers may be behind the leader, causing stale reads. Handle with read-your-writes (route a user's

reads to the leader after writes), monotonic reads, or sticky routing, and monitor lag.

Q58. What is sharding (partitioning) and what are the strategies?

Sharding splits data across multiple databases. Strategies are range-based, hash-based,

directory-based (lookup) and geographic partitioning. Hash with consistent hashing gives even

distribution; range supports range queries.

Q59. What problems does sharding introduce?

Cross-shard joins and transactions, hotspots, rebalancing difficulty, operational complexity and the

need for a shard key that distributes load evenly.

Q60. How do you choose a good shard key?

Pick a key with high cardinality, even access distribution and alignment with common query patterns so

most queries hit one shard. Avoid monotonically increasing keys that create hot shards.

Q61. What is resharding and how can it be done with minimal downtime?

Resharding rebalances data when capacity changes. Use consistent hashing, many logical shards

mapped to fewer physical nodes, dual writes and background migration with verification before cutover.

Q62. What is denormalization and when is it useful?

Denormalization duplicates data to avoid joins and speed up reads, trading storage and write

complexity and consistency risk. It is common in read-heavy systems and NoSQL.

Q63. What are the types of NoSQL databases?

Key-value (Redis, DynamoDB), document (MongoDB, Couchbase), wide-column (Cassandra, HBase),

graph (Neo4j) and time-series (InfluxDB, Prometheus). Each suits particular access patterns.

Q64. When would you use a graph database?

When relationships are first-class and queries traverse many hops, such as social networks,

recommendations, fraud detection and knowledge graphs.

Q65. When would you use a time-series database?

For append-heavy, timestamped metrics and events like monitoring, IoT and financial ticks, where you

need efficient compression, downsampling and time-range queries.

Q66. What is connection pooling and why does it matter?

A pool reuses established database connections instead of creating one per request, reducing latency

and protecting the database from connection exhaustion.

Q67. What is the N+1 query problem?

Fetching a list with one query and then issuing an additional query per item. Fix by joins, batch fetching

or eager loading.

Q68. What is Write-Ahead Logging (WAL)?

Changes are first appended to a durable log before being applied to data files, enabling crash recovery

and replication. PostgreSQL and many databases rely on it.

Q69. What is the difference between OLTP and OLAP?

OLTP handles many short transactional operations on current data with row stores. OLAP runs

complex analytical queries over large historical data, usually using column stores and data

warehouses.

Q70. What are row-oriented and column-oriented stores?

Row stores keep all columns of a row together, good for transactional access. Column stores keep

each column together, enabling better compression and fast aggregations in analytics (Redshift,

BigQuery, ClickHouse).

Q71. How do you handle unique ID generation in a distributed system?

Options include UUIDs, database auto-increment with different offsets, ticket servers, and

Snowflake-style 64-bit IDs combining timestamp, machine ID and sequence, which are time-sortable

and require no coordination.

Q72. How would you design database backups and disaster recovery?

Use periodic full snapshots plus incremental logs for point-in-time recovery, store copies in other

regions, test restores regularly and define RPO and RTO targets.

Distributed Systems Theory

Q73. What is the CAP theorem?

A distributed data store can provide at most two of Consistency, Availability and Partition tolerance

simultaneously. Since partitions are unavoidable, the real choice during a partition is between

consistency and availability.

Q74. What is the PACELC theorem?

It extends CAP: if there is a Partition choose between Availability and Consistency, Else (normal

operation) choose between Latency and Consistency. It captures trade-offs when the system is

healthy.

Q75. What are strong, eventual and causal consistency?

Strong consistency means reads always see the latest write. Eventual consistency means replicas

converge if no new writes occur. Causal consistency preserves the order of causally related operations.

Q76. What is linearizability versus serializability?

Linearizability is a single-object real-time ordering guarantee, as if operations happen atomically at one

point in time. Serializability is a multi-object transaction guarantee that results equal some serial order,

not necessarily real-time.

Q77. What is quorum and how does it work?

A quorum requires a minimum number of nodes to agree. With N replicas, write quorum W and read

quorum R, choosing R + W > N guarantees reads overlap with the latest write.

Q78. What is a consensus algorithm?

A protocol by which distributed nodes agree on a single value despite failures. Paxos and Raft are

widely used for leader election and replicated logs in etcd, ZooKeeper and Consul.

Q79. How does Raft work at a high level?

Nodes are leader, follower or candidate. A leader is elected by majority vote in a term, receives client

writes, appends them to its log and replicates to followers; an entry commits once a majority stores it.

Q80. What is leader election and why is it needed?

It selects one node to coordinate work (for example a primary database or scheduler) to avoid conflicts.

It is implemented with consensus systems or lease-based locks, with fencing tokens to prevent

split-brain.

Q81. What is split-brain and how do you prevent it?

Split-brain occurs when partitioned nodes each believe they are the leader and accept conflicting

writes. Prevent with majority quorums, fencing tokens, STONITH and odd-sized clusters.

Q82. What is two-phase commit (2PC) and its drawbacks?

A coordinator asks all participants to prepare and then commit or abort. It provides atomicity across

nodes but blocks if the coordinator fails and has high latency, so it scales poorly.

Q83. What is the Saga pattern in distributed transactions?

A saga is a sequence of local transactions with compensating actions if a step fails. It provides eventual

consistency without distributed locks, using choreography (events) or orchestration (a coordinator).

Q84. What is idempotency and why is it critical?

An operation is idempotent if repeating it has the same effect as doing it once. It makes retries safe,

using idempotency keys, unique constraints or conditional updates, particularly for payments.

Q85. What delivery semantics exist in messaging?

At-most-once (may lose), at-least-once (may duplicate) and exactly-once (effectively once, achieved

through idempotent consumers or transactional processing). At-least-once plus idempotency is the

practical default.

Q86. What are vector clocks and Lamport timestamps?

Lamport timestamps give a logical ordering of events using counters. Vector clocks keep a counter per

node and can detect concurrent (conflicting) updates, as used in Dynamo-style systems.

Q87. What is a gossip protocol?

Nodes periodically exchange state with random peers so information spreads epidemically. It is used

for membership, failure detection and metadata propagation in Cassandra and Consul.

Q88. What is a CRDT?

Conflict-free Replicated Data Types are data structures that can be updated independently on replicas

and merge deterministically without coordination, giving strong eventual consistency (counters, sets,

collaborative text).

Q89. How do you handle conflict resolution in multi-leader systems?

Use last-write-wins (simple but lossy), vector-clock-based detection with application merge, CRDTs, or

avoid conflicts by routing writes for a record to a single leader.

Q90. What is the difference between synchronous and asynchronous replication?

Synchronous replication waits for replicas to acknowledge, giving durability and consistency but higher

latency and lower availability. Asynchronous replication acknowledges immediately, giving lower

latency but potential data loss on failover.

Q91. What are the fallacies of distributed computing?

Assumptions such as the network is reliable, latency is zero, bandwidth is infinite, the network is

secure, topology does not change, there is one administrator, transport cost is zero and the network is

homogeneous. Designs must handle their falsity.

Q92. What is a distributed lock and what pitfalls does it have?

A distributed lock gives mutual exclusion across processes (Redis, ZooKeeper, etcd). Pitfalls include

clock drift, expired leases while a process is paused, and lack of fencing tokens, so locks should have

TTLs and fencing.

Messaging, Queues and Streaming

Q93. Why use a message queue?

Queues decouple producers from consumers, smooth traffic spikes, enable asynchronous processing

and retries, and improve resilience because a slow or failed consumer does not block the producer.

Q94. What is the difference between a message queue and publish-subscribe?

In a queue each message is consumed by one consumer (competing consumers). In pub-sub each

message is delivered to all subscribers of a topic.

Q95. What is Kafka and how does it work?

Kafka is a distributed, partitioned, replicated commit log. Producers append messages to topic

partitions, brokers persist them, and consumer groups read at their own offsets, enabling high

throughput and replay.

Q96. How does Kafka guarantee ordering?

Ordering is guaranteed only within a partition. Messages with the same key go to the same partition, so

use an entity ID as the key when order per entity matters.

Q97. What are consumer groups in Kafka?

A consumer group shares the partitions of a topic among its consumers so each partition is read by

exactly one consumer in the group, giving parallelism and scalability. Different groups consume

independently.

Q98. How do you scale consumers in Kafka?

Add consumers to the group up to the number of partitions; more partitions allow more parallelism.

Partition count must be planned because increasing it later changes key-to-partition mapping.

Q99. What is a dead letter queue?

A separate queue that stores messages that failed processing after the maximum number of retries, so

they can be inspected, fixed and replayed without blocking the main flow.

Q100. How do you handle duplicate messages?

Make consumers idempotent using unique message IDs stored in a dedup table or cache, use

conditional writes or upserts, and rely on broker features such as idempotent producers where

available.

Q101. What is backpressure and how do you handle it?

Backpressure occurs when producers outpace consumers. Handle with bounded queues, rate limiting,

load shedding, scaling consumers, and reactive streams that signal demand upstream.

Q102. What is the difference between Kafka, RabbitMQ and SQS?

Kafka is a log for high-throughput streaming with retention and replay. RabbitMQ is a feature-rich

broker with flexible routing and acknowledgements. SQS is a fully managed, scalable queue with

simple semantics and no ordering unless FIFO queues are used.

Q103. What is the Outbox pattern?

A service writes business data and an outgoing event to an outbox table in the same local transaction,

and a relay publishes the events to the broker. It avoids the dual-write problem between database and

messaging.

Q104. What is event-driven architecture?

Components communicate by producing and reacting to events rather than direct calls, giving loose

coupling and scalability, but making flow harder to trace and requiring careful handling of ordering and

duplicates.

Q105. What is stream processing versus batch processing?

Batch processes large bounded datasets periodically (MapReduce, Spark), with high throughput and

latency in minutes to hours. Stream processing handles unbounded data continuously with low latency

Q106. What is Lambda versus Kappa architecture?

Lambda runs separate batch and speed layers with a serving layer merging results. Kappa uses a

single streaming pipeline with a replayable log, reducing duplicate logic.

Kafka supports idempotent producers and transactions that atomically write to multiple partitions and

commit consumer offsets, giving exactly-once processing within Kafka-to-Kafka pipelines.

API Design and Microservices

Q108. What is REST and what are its constraints?

REST is an architectural style with client-server, statelessness, cacheability, uniform interface, layered

system and optional code-on-demand. Resources are identified by URIs and manipulated with HTTP

methods.

Q109. What is the difference between REST, GraphQL and gRPC?

REST is simple, cacheable and resource-oriented. GraphQL lets clients request exactly the data they

need through a single endpoint, avoiding over-fetching. gRPC uses HTTP/2 and Protocol Buffers for

fast, strongly typed service-to-service calls.

Q110. What is idempotency in HTTP methods?

GET, PUT, DELETE, HEAD and OPTIONS are idempotent, while POST is not. Making POST safe to

retry requires an Idempotency-Key header handled by the server.

Q111. How do you version an API?

Use URI versioning (/v1/), header or media-type versioning, or additive backward-compatible changes.

Maintain deprecation policies and avoid breaking existing clients.

Q112. How do you implement pagination?

Offset/limit is simple but slow and unstable for large or changing data. Cursor (keyset) pagination uses

the last seen key for consistent, efficient paging and is preferred for feeds.

Q113. What is an API gateway?

A single entry point that handles routing, authentication, rate limiting, request aggregation, caching and

monitoring for backend services, simplifying clients and centralising cross-cutting concerns.

Q114. How would you design rate limiting?

Choose an algorithm (token bucket, leaky bucket, fixed window, sliding window log or counter), store

counters in Redis keyed by user, IP or API key, return HTTP 429 with Retry-After headers, and make

limits configurable per tier.

Q115. What are the pros and cons of microservices?

Pros: independent deployment and scaling, technology freedom, fault isolation and team autonomy.

Cons: network latency, distributed transactions, operational overhead, observability and data

consistency challenges.

Q116. How should you split a system into microservices?

Use Domain-Driven Design bounded contexts, align services with business capabilities and teams,

keep services loosely coupled with high cohesion, and give each service ownership of its data.

Q117. Should microservices share a database?

Generally no. A database per service preserves autonomy and prevents hidden coupling; data is

shared through APIs or events, accepting eventual consistency.

Q118. What is service discovery?

A mechanism by which services find each other's network locations dynamically. Client-side discovery

queries a registry (Eureka, Consul), while server-side discovery uses a load balancer or Kubernetes

DNS and Services.

Q119. How do services communicate synchronously and asynchronously?

Synchronous communication uses HTTP/REST or gRPC with timeouts, retries and circuit breakers.

Asynchronous communication uses message brokers or event streams, improving decoupling and

resilience.

Q120. What is the Circuit Breaker pattern?

It stops calls to a failing dependency after a failure threshold, failing fast and later probing in a half-open

state to see if the dependency has recovered, preventing cascading failures.

Q121. What is the Strangler Fig pattern?

Incrementally replacing a legacy monolith by routing specific functionality to new services behind a

facade until the old system can be retired, reducing migration risk.

Q122. What is CQRS and when should you use it?

Command Query Responsibility Segregation separates write and read models so each can be

optimised and scaled independently. Use it for complex domains or very different read and write loads,

accepting added complexity.

Q123. What is Event Sourcing?

Persisting state as an immutable sequence of events and deriving current state by replay. It provides

audit trails and time travel, but needs snapshots and event schema evolution.

Q124. How do you handle authentication and authorization in a distributed system?

Use OAuth 2.0 and OpenID Connect with short-lived JWT access tokens validated at the gateway or

services, mTLS between services, and centralised policy for RBAC or ABAC.

Q125. What is the difference between orchestration and choreography?

Orchestration uses a central coordinator to direct service interactions, giving visibility and control.

Choreography has services react to each other's events, giving loose coupling but harder tracing.

Q126. What is the Backend-for-Frontend (BFF) pattern?

A dedicated backend per client type (web, mobile) that aggregates and shapes data for that

experience, reducing chattiness and avoiding one-size-fits-all APIs.

Q127. How do you design backward-compatible schema changes?

Use additive changes, optional fields with defaults, expand-and-contract migrations, schema registries

with compatibility checks, and never remove or repurpose fields until all consumers have migrated.

Reliability, Observability and Security

Q128. How do you design for high availability?

Eliminate single points of failure with redundancy across availability zones and regions, use health

checks and automated failover, replicate data, deploy with rolling or blue-green strategies and test

failure scenarios.

Q129. What is the difference between active-active and active-passive?

Active-active runs all nodes serving traffic simultaneously for better utilisation and fast failover but

needs conflict handling. Active-passive keeps a standby that takes over on failure, which is simpler but

wastes capacity.

Q130. What are RPO and RTO?

Recovery Point Objective is the maximum acceptable data loss measured in time, and Recovery Time

Objective is the maximum acceptable time to restore service after a disaster.

Q131. What is graceful degradation?

Continuing to provide core functionality when parts of the system fail by disabling non-essential

features, serving cached or default data, or reducing quality, instead of failing entirely.

Q132. What are timeouts, retries and exponential backoff?

Timeouts bound waiting time, retries re-attempt transient failures, and exponential backoff with jitter

spaces retries to avoid retry storms. Retry only idempotent operations and cap attempts.

Q133. What is load shedding?

Deliberately rejecting or dropping low-priority requests when the system is overloaded to protect

latency and availability for critical traffic.

Q134. What is the bulkhead pattern?

Isolating resources such as thread pools or connection pools per dependency so that failure or

slowness in one does not exhaust resources for others.

Q135. What are blue-green and canary deployments?

Blue-green keeps two identical environments and switches traffic from old to new instantly, with easy

rollback. Canary gradually shifts a small percentage of traffic to the new version while monitoring

metrics.

Q136. What are feature flags?

Runtime switches that enable or disable features without redeploying, supporting gradual rollouts, A/B

tests, kill switches and decoupling deployment from release.

Q137. What are the three pillars of observability?

Metrics (numeric time-series), logs (event records) and traces (end-to-end request paths across

services). Together they allow diagnosing unknown problems.

Q138. What is distributed tracing?

It tracks a request across services using a trace ID propagated in headers, with spans for each hop,

helping find latency bottlenecks and failures (Jaeger, Zipkin, OpenTelemetry).

Q139. What are the golden signals for monitoring?

Latency, traffic, errors and saturation, as defined in Google's SRE book. Alerts should focus on

symptoms visible to users.

Q140. Why use percentiles (p95, p99) instead of averages for latency?

Averages hide the slow tail. Percentiles show the experience of the slowest users, and tail latency is

amplified in systems that fan out to many services.

Storage, Search and Data Processing

Q146. What is the difference between block, file and object storage?

Block storage provides raw volumes for databases and VMs (EBS), file storage offers hierarchical

shared file systems (NFS, EFS), and object storage stores objects with metadata via HTTP APIs at

huge scale and low cost (S3).

Q147. Why store media files in object storage rather than in a database?

Object storage is cheaper, scalable, durable, integrates with CDNs and offloads large binary traffic from

databases. The database stores only metadata and URLs.

Q148. How do pre-signed URLs help uploads and downloads?

The server generates a time-limited signed URL so clients upload or download directly to or from object

storage, avoiding passing large files through application servers and keeping the bucket private.

Q149. How does a search engine index work?

Documents are tokenized and an inverted index maps each term to the list of documents containing it.

Queries look up terms and rank results by relevance (TF-IDF, BM25). Elasticsearch and Solr are built

on Lucene.

Q150. How do you keep a search index in sync with the primary database?

Use change data capture or event streams to update the index asynchronously, or dual write via an

outbox, and run periodic reindexing. Accept slight staleness.

Q151. What is a Bloom filter and where is it used?

A probabilistic bit-array structure that tests set membership with no false negatives but possible false

positives. It is used to avoid unnecessary disk or database lookups in caches, LSM trees and crawlers.

Q152. What is HyperLogLog?

A probabilistic algorithm to estimate the number of distinct elements using very little memory (about 12

KB in Redis) with roughly 1% error, used for unique visitor counts.

Q153. What is a Count-Min Sketch?

A probabilistic structure for estimating frequencies of items in a stream using sublinear space, useful for

top-K and heavy-hitter detection.

Q154. What are Trie and Geohash structures used for in system design?

A trie supports prefix search and autocomplete. Geohash encodes latitude and longitude into strings so

nearby places share prefixes, enabling proximity queries, as do quadtrees and S2 cells.

Q155. What is MapReduce?

A programming model that processes large datasets in parallel through a map phase that emits

key-value pairs and a reduce phase that aggregates by key. Spark has largely replaced it with

in-memory processing.

Q156. What is a data lake versus a data warehouse?

A data lake stores raw data of any format cheaply (schema on read), while a data warehouse stores

curated, structured data optimised for analytics (schema on write).

Q157. What is Change Data Capture (CDC)?

Capturing row-level changes from a database's transaction log and streaming them to other systems

(Debezium), keeping caches, search indexes and warehouses in sync without dual writes.

Classic Design Problems: URL Shortener, Rate Limiter,

Pastebin

Q158. Design a URL shortener: what are the core requirements and API?

Generate a short unique alias for a long URL, redirect quickly, support optional custom aliases and

expiry, and provide analytics. APIs: POST /shorten (longUrl) returns shortUrl, and GET /{code} returns

a 301 or 302 redirect.

Q159. How do you generate unique short codes for a URL shortener?

Use a base62-encoded counter or distributed ID (Snowflake), a pre-generated key service handing out

unused keys, or a hash of the URL with collision checks. A 7-character base62 code gives about 3.5

trillion combinations.

Q160. Should a URL shortener use 301 or 302 redirects?

301 is permanent and cached by browsers, reducing load but losing analytics. 302 is temporary and

ensures every click reaches the server, so use 302 when tracking clicks.

Q161. How would you scale reads and storage for a URL shortener?

The workload is read-heavy, so use a cache (Redis) for hot codes, a CDN or edge redirects, replicas

for reads, and shard the key-value store by short code. Estimating 100M new URLs a month at 500

bytes gives about 600 GB over 10 years.

Q162. Design a distributed rate limiter: which algorithms and storage do you use?

Token bucket (allows bursts), leaky bucket (smooth output), fixed window (simple, edge bursts), sliding

window log (accurate, memory heavy) and sliding window counter (balanced). Store counters in Redis

with atomic Lua scripts or INCR with expiry.

Q163. How do you make a rate limiter work across many servers without race conditions?

Use a central store such as Redis with atomic operations, or local counters synced periodically for

approximate limits. Place it at the API gateway and fail open or closed deliberately if the store is

unreachable.

Q164. Design Pastebin: how do you store and serve content?

Store paste text in object storage and metadata (key, owner, expiry, language) in a database, generate

keys with a key-generation service, cache popular pastes, and run a cleanup job for expired pastes.

Classic Design Problems: Messaging, Feeds and Social

Q165. Design a chat application like WhatsApp: what are the key components?

Persistent WebSocket connections via connection gateways, a message service, a presence service, a

message store, push notification service and a queue for offline delivery. Messages get IDs and

delivery states (sent, delivered, read).

Q166. How do you ensure message ordering and delivery in a chat system?

Use per-conversation sequence numbers or time-sortable IDs, partition messages by conversation ID,

require acknowledgements with retries, and deduplicate by message ID.

Q167. How would you store chat messages at scale?

Use a write-optimised wide-column store (Cassandra, HBase) partitioned by conversation ID and

clustered by message ID/time, because access is mostly recent messages per conversation.

Q168. How do you support group chat and presence?

Fan out group messages to member connections via the connection gateways using a membership

lookup; for large groups use pub-sub channels. Presence uses heartbeats with a TTL in Redis and only

publishes changes to relevant contacts.

Q169. Design a news feed (Facebook or Twitter timeline): what are the main approaches?

Fan-out on write (push) precomputes each follower's feed when a post is created, giving fast reads but

expensive for celebrities. Fan-out on read (pull) builds the feed at read time. A hybrid pushes for normal

users and pulls for celebrities.

Q170. How do you handle celebrity users in a feed system?

Do not push their posts to millions of follower feeds; store them separately and merge them into the

feed at read time, while pushing for regular users.

Q171. How do you rank a news feed?

Fetch candidate posts, extract features (recency, affinity, engagement, content type), score with an ML

model and blend with business rules, returning the top N with cursor-based pagination.

Q172. Design a notification system: what are the main components?

Event producers publish to a queue, a notification service applies user preferences, templating, rate

limiting and deduplication, and per-channel workers send via APNs, FCM, SMS or email providers with

retries and delivery tracking.

Q173. Design Twitter's tweet storage and timeline at a high level.

Store tweets in a sharded database keyed by tweet ID (Snowflake), a social graph store for follows,

home timelines in Redis lists per user, media in object storage with a CDN, and search through an

inverted index.

Q174. How would you design a "like" or "view" counter at massive scale?

Buffer increments in memory or a stream, aggregate them in batches, and write sharded counters to

avoid hot rows. Accept eventual consistency and use approximate counters where exact values are not

needed.

Q175. Design a trending topics or top-K system.

Stream events into a processor (Flink/Kafka Streams), count with a Count-Min Sketch or windowed

aggregation, maintain a heap of top-K per time window, and serve results from a cache refreshed

periodically.

Classic Design Problems: Media, Storage and Collaboration

Q176. Design YouTube or Netflix video streaming: what is the high-level architecture?

Uploads go to object storage, a pipeline transcodes into multiple resolutions and formats, segments the

video for adaptive bitrate streaming (HLS or DASH), and a CDN delivers segments close to viewers

Q177. How does adaptive bitrate streaming work?

The video is split into short segments encoded at several bitrates, and the player picks the best bitrate

for current bandwidth and switches dynamically, reducing buffering.

Q178. Design Dropbox or Google Drive: how do you handle file sync?

Split files into chunks (e.g. 4 MB), hash each chunk, upload only changed chunks (deduplication), store

chunks in object storage and metadata in a database, and notify clients of changes through long polling

or push.

Q179. How do you resolve edit conflicts in file sync?

Use version vectors or revision numbers; if two clients edit the same version, keep both as conflicted

copies or merge, and let the user resolve them.

Q180. Design Google Docs real-time collaboration: which techniques are used?

Operational Transformation or CRDTs merge concurrent edits, WebSocket connections broadcast

operations to collaborators, and a server sequences operations and persists snapshots and operation

logs.

Q181. Design Instagram or an image-sharing service.

Upload images to object storage, generate thumbnails asynchronously, store metadata and

relationships in databases, serve through a CDN, and build feeds with a hybrid fan-out approach.

Q182. Design a video conferencing system (Zoom).

Use WebRTC with signalling servers for session setup, STUN/TURN for NAT traversal, and SFU media

servers that forward streams selectively, with adaptive quality and regional media servers for low

latency.

Q183. Design a distributed file system like GFS or HDFS.

A master (NameNode) holds metadata and chunk locations, chunk servers store replicated large blocks

(typically 3 copies), clients read data directly from chunk servers, and heartbeats drive re-replication

when nodes fail.

Q184. Design a distributed key-value store like DynamoDB.

Partition data by consistent hashing, replicate to N nodes, use quorum reads and writes, vector clocks

or versioning for conflicts, hinted handoff and anti-entropy (Merkle trees) for repair, and gossip for

membership.

Q185. Design a web crawler.

A URL frontier queue with prioritisation and politeness per host, distributed fetchers, DNS caching, a

content parser and deduplication (hashing or simhash), robots.txt compliance, and storage of pages for

indexing.

Q186. Design a typeahead or autocomplete system.

Store popular queries in a trie with top suggestions cached at each node, update it from query logs

offline, serve from memory behind a cache with a small TTL, and shard by prefix.

Classic Design Problems: Commerce, Location and

Q187. Design an e-commerce system such as Amazon: what are the main services?

Catalogue and search, cart, inventory, order, payment, shipping and recommendation services, each

with its own datastore, connected through events. Inventory and payments require strong consistency;

browsing can be eventually consistent.

Q188. How do you prevent overselling inventory during a flash sale?

Use atomic decrement in Redis or conditional database updates, reserve stock with expiry during

checkout, queue requests to smooth load and apply rate limiting and a virtual waiting room.

Q189. Design a payment system: what are the key concerns?

Idempotency keys to avoid double charges, double-entry ledger, reconciliation with payment providers,

PCI-compliant tokenization, retries with state machines and audit logging. Prefer strong consistency

and exactly-once effects.

Q190. Design a ride-sharing service like Uber.

Drivers send periodic location updates indexed with geohash or quadtree/S2 in memory, a matching

service finds nearby available drivers, trips follow a state machine, and surge pricing uses

demand-supply stats per cell.

Q191. Design a proximity service like Yelp or nearby friends.

Index places using geohash, quadtree or S2 cells, query the target cell and its neighbours, filter by

distance and rank by relevance. Static places can live in a database with a geospatial index; moving

users use in-memory structures.

Q192. Design a hotel or ticket booking system.

Model inventory per date, prevent double booking with transactions or optimistic locking, place

temporary holds with TTLs, process payments with idempotency and expire unpaid holds with

background jobs.

Q193. Design a scalable unique ID generator.

Use a Snowflake-style 64-bit ID: timestamp bits, datacenter and machine bits, and a per-millisecond

sequence. It is roughly time-ordered, needs no coordination and handles clock drift by waiting or

rejecting.

Q194. Design a job scheduler or distributed cron.

Store jobs with schedules in a database, have schedulers poll for due jobs and enqueue them, workers

pull and execute with leases and heartbeats, ensure at-least-once execution with idempotent jobs, and

elect a leader to avoid duplicates.

Q195. Design a metrics and monitoring system.

Agents push or the server pulls metrics into a time-series database, with a stream aggregator for

rollups, downsampling for retention, an alerting engine evaluating rules, and dashboards on top.

Q196. Design a log aggregation system.

Agents ship logs to a Kafka buffer, a processing layer parses and enriches them, storage in

Elasticsearch or object storage with tiered retention, and a query and alerting layer.

Q197. Design an API for a leaderboard.

Use Redis sorted sets for scores with ZADD and ZREVRANGE, shard by leaderboard or score range

for scale, persist snapshots to a database and compute global rankings periodically for very large user

bases.

Q198. Design a recommendation system at a high level.

Collect user events, build candidate generation (collaborative filtering, content-based, embeddings and

nearest-neighbour search), rank candidates using ML models with features from a feature store, and

serve results with caching and A/B testing.

Q199. How would you design a system to handle a 10x traffic spike?

Autoscale stateless tiers, add caching and CDN, use queues to buffer writes, apply rate limiting and

load shedding, scale databases with replicas and sharding in advance, and load test capacity ahead of

known events.

Q200. How would you migrate a large system to a new database with zero downtime?

Dual write to old and new stores, backfill historical data, verify consistency with comparisons and

shadow reads, gradually shift reads, then cut over writes and retire the old store with a rollback plan.
